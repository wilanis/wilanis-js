# X207

- **Family:** X -- plugin rules, @storage (@wilanis/plugin-storage)
- **Status:** live, since 0.1.0
- **Made in:** `packages/plugin-storage/src/rules.ts`
- **Proved by:** `packages/plugin-storage/test/rules.test.ts` (`X207 one collection name, two shapes: the pair is the collection, so they would be one table`)

## Refuses when

Two stores over the same connection declare a collection of the same name, and the two declare different shapes. A
collection is the pair of its connection and its name, so the two declarations are one table in the engine, and one
table keeps one shape. Two stores that name the same collection with the same shape are how two features share a
collection on purpose, and are not refused. The refusal sits at `collections/<name>/of` of the second store the
loader finds.

## Example

Plant a second store on the customers connection whose `latest` keeps customers:

```
X207  @features/customers/data/other.store.json#collections/latest/of
    'latest' over this connection already keeps @features/customers/domain/TierLatest.shape.json, declared by @features/customers/data/customers.store.json, and here it keeps @customers/domain/Customer.shape.json
    → rename one, or give both the same shape if the collection is meant to be shared
```

## Fix

Rename one of the two collections if they are meant to be different tables. If they are meant to be the same table,
give both the same shape.
