## Refuses when

A data graph composes a value of a shape a field invariant holds over, and an effect of that graph reads it. The
value is composed where a node's native operation answers the shape (`#make`, `#merge`, or a `map` of them) and does
not simply re-type what an effect answered. The effect may read it directly or through the nodes between. The
refusal sits at `nodes/<id>` of the node that makes the value. The message names the shape, the invariant that
guards it, the effect, and any nodes the value passed through on the way.

A data graph translates between the domain and the world. The value the business decides on is made in a domain
graph and handed down whole, as the data graph's `in`, where the compiler guards it again (RFC 0035). A data graph
that composes the business value on its way to a write is the shape that let the example store a customer its own
invariant refused.

Not refused:

- a made value no effect reads, such as `kept` in `keep-customer`, which turns what the store answered back into
  a `Customer` for the graph's answer;
- a read site, whatever reads it: a node that is itself an effect (a `#find`), or one that reads its whole value from
  an effect's answer (a `#make` of `{{stored.record}}`, or a `map` over `{{found}}` that binds each element to a
  `#make` as its `value`). A `map` that lays a change over each element (`#merge` with the element bound as `base`)
  composes, as one `#merge` does.

A read site that L016 leaves alone is still guarded where the compiler cannot prove the invariant holds there: the
exemption is L016's reading of the site, and the guard reads it as written.

## Example

Move `update-customer`'s `#merge` into a data graph that `customer.update` is bound to, and have it `#put` what it
made:

```
L016  @features/customers/data/kept-update.graph.json#nodes/customer
    data graph makes a Customer, which 'A customer is reachable' (@features/customers/domain/a-customer-is-reachable.invariant.json) guards, and the effect 'stored' reads it
    → a data graph translates; make the record in a domain graph and hand it to this one whole, as its in
```

## Fix

Make the value in a domain graph and hand it to an operation that takes the whole shape; the data graph behind that
operation takes it as its `in` and writes `"record": "{{in}}"`. The example's `update-customer` and `keep-customer`
are that pair, and `wilanis new graph <path> --port <port>` and `--store <store> --collection <name>` scaffold it.
Where the store generates the key, the domain graph asks for one first, through an operation such as the example's
`nextId`.
