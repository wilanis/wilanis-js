# X215

- **Family:** X -- plugin rules, @storage (@wilanis/plugin-storage)
- **Status:** live, since 0.1.0
- **Made in:** `packages/plugin-storage/src/kept.ts`
- **Proved by:** `packages/runtime/test/sabotage-storage.test.ts` (`X215 a write through a kept store, at the put of keep-customer and at every other write`; `X215 the ensure a startup step reaches, and X216 the store beside it on the connection that says none`)

## Refuses when

A call names a store that says `keptBy`, and the call writes through it or prepares it. A store that says `keptBy`
holds records another tree keeps: that tree writes them and runs `wilanis migrate` over them, and this tree only
reads them (RFC 0042). The calls refused are `@storage/store.port.json#put`, `#patch`, `#remove` and `#newKey`, and
`@storage/storage.port.json#ensure`. `#newKey` is refused with the writes, because a key is made to write a record,
and an engine may write to reserve one. `ensure` is refused because it creates the collections with this tree's
shapes and records them under this tree's name. A read (`#get`, `#find`, `#count`) is allowed: it is why the store
is there.

The refusal sits at the call's `in`: `nodes/<id>/in` in a data graph, `operations/<name>/in` in a binding.

## Example

Say that the billing tree keeps `@customers/data/customers.store.json` (`"keptBy": "billing"`, without its
`renamed` and `defaults`), and every write through it is refused, the `put` of keep-customer first:

```
X215  @features/customers/data/keep-customer.graph.json#nodes/stored/in
    this puts into customers of @features/customers/data/customers.store.json, which the billing tree keeps (keptBy)
    → a kept store is read only: ask the billing tree for the change through a port it exposes, or remove keptBy if this tree keeps the collection
```

The binding that delegates the customers port's `prepare` to `ensure` reads `this prepares
@features/customers/data/customers.store.json, which the billing tree keeps (keptBy)`.

## Fix

If the other tree keeps the records, ask it for the change: call an operation of a port that tree exposes, and let
its graphs write. Remove the startup step that prepares the store; the keeping tree's `wilanis migrate` creates the
collections. If this tree keeps the collection after all, remove `keptBy` from the store.
