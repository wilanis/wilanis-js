# G021

- **Family:** G -- graphs
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/graph-nodes.ts`
- **Proved by:** `packages/runtime/test/sabotage-catch.test.ts` (`refuses a caught node that is not a node, is the switch, or is not read by it`)

## Refuses when

An entry of a switch's `catch` does not name a node this switch reads, or does not route its fault to another node of
the graph. Of the caught node: it is no node of the graph (`catch names unknown node 'nope'`), it is the switch itself
(`switch catches its own fault`), none of the switch's `in` reads it (`catches 'customer', which none of this switch's
in reads`), or another switch catches it too (`'fetched' is caught by both 'outcome' and 'later'`, refused at the
second). Of where the fault goes: no node of the graph (`catch routes 'fetched' to unknown node 'nope'`), the node that
broke (`catch routes 'fetched' to itself; what broke cannot say what breaking means`), or the switch (`catch routes
'fetched' to the switch itself`). The refusal sits at `nodes/<switch>/catch/<caught>`.

## Example

Have `get-row`'s switch catch `customer`, a node it routes to but does not read:

```
G021  @features/customers/data/get-row.graph.json#nodes/outcome/catch/customer
    catches 'customer', which none of this switch's in reads
    → catch names a node this switch reads and routes its fault to a node of this graph, e.g. "catch": { "asked": "unreachable" }
```

A catch routed to a node that is not there leaves the intended target routed by nothing, so G010 follows at
`out/from`; it goes with this fix.

## Fix

Key the entry by an effect the switch reads through its `in`, and route it to a node of this graph other than that one
and the switch, usually a `refuse` of a reason the trigger maps: `"catch": { "fetched": "unreachable" }`. Where two
switches catch the same node, keep the catch on one.
