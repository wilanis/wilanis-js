# B004

- **Family:** B -- bindings, profiles and startup
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/profiles.ts`
- **Proved by:** `packages/runtime/test/sabotage-project.test.ts` (`B004 a profile whose binding implements another port`)

## Refuses when

A profile's `bindings` map a domain port to the binding that meets it under that profile, and the binding named must
implement that port. The refusal sits on the project at `profiles/<name>/bindings` and names the binding, the port it
implements, and the port the profile chose it for.

## Example

Give the customers REST binding another `port`. The profile `live` still chooses it for the customer port; the binding
is also refused as R001, since the port it now names does not exist:

```
B004  @project.json#profiles/live/bindings
    profile 'live': binding '@customers/data/customers-rest.binding.json' implements '@customers/other.port.json', not '@customers/domain/customer.port.json'
    → name a binding whose port is '@customers/domain/customer.port.json', or correct the port in the profile
```

## Fix

Decide which side is wrong. If the profile named the wrong binding, name one whose `port` is the port it is keyed by
(`wilanis ls binding`). If the binding's `port` was changed by mistake, set it back. If the profile keyed the wrong
port, correct the key.
