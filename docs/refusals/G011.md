# G011

- **Family:** G -- graphs
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/graph-nodes.ts`
- **Proved by:** `packages/runtime/test/sabotage-unproved.test.ts` (`G011 a rule whose when is not a boolean`)

## Refuses when

A switch's rule has a `when` that does not parse, does not type against the switch's inputs, or types to something
other than a boolean. The expression reads only the names under the switch's `in`. The message is `rule <n>: '<when>'
is <type>, not boolean`, or `rule <n>: ` and what the parser or the type check said. The refusal sits at
`nodes/<id>/rules/<n>/when`.

## Example

Write the first rule of `list-rows`'s `outcome` as a bare number:

```
G011  @features/customers/data/list-rows.graph.json#nodes/outcome/rules/0/when
    rule 0: 'status' is number, not boolean
    → compare the value, as in a.b == 1, so when answers a boolean
```

An unparsable `when` (`status >=`) reads `rule 0: unexpected end of 'status >='` with the hint `write when as an
expression over this node's inputs`. Either way a G004 follows at the node the rule routed, whose read is no longer
proved present.

## Fix

Write `when` as a comparison or a test over the switch's inputs (`status == 404`, `has(body)`). A name it reads that is
not an input is added under the switch's `in` first. When G004s follow a G011, fix the G011: they are its shadow.
