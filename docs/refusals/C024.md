# C024

- **Family:** C -- connections, settings and stores
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/profiles.ts`
- **Proved by:** `packages/runtime/test/sabotage-profiles.test.ts` (`C024 a profile extending one the project does
  not declare, itself, or one that extends another`)

## Refuses when

A profile's `extends` (RFC 0043) names a profile it cannot start from:

- a profile the project does not declare under `project.json → profiles`;
- the profile itself;
- a profile that itself extends another declared profile. There is one level: the profile named extends nothing,
  so a reader of a child opens one more profile and never a chain.

Where `extends` is wrong, the profile is read as if it extended nothing, so the rest of the checker judges its own
written choices alone. A parent whose own `extends` names itself or no declared profile is refused at its own line,
and its children are judged again once it is repaired. The refusal points at the child's `extends`.

## Example

Make `production-worker` extend `production-scheduler`, which extends `production`:

```
C024  @project.json#profiles/production-worker/extends
    profile 'production-worker' extends 'production-scheduler', which extends 'production'; a profile extends one
    that extends nothing
    → extend 'production' directly and write what 'production-scheduler' changes, or remove extends from
      'production-scheduler'
```

## Fix

Name a declared profile that extends nothing; the hint lists them where the name was wrong. For a chain, extend the
grandparent directly and write under the child what the middle profile changes, or remove `extends` from the middle
profile and write its choices out.
