# I005

- **Family:** I -- invariants
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/invariant-holds.ts`
- **Proved by:** `packages/runtime/test/sabotage-invariants.test.ts` (`I005 a site whose every read is literal and contradicts the rule`, `I005 a literal gold account that carries no note, and none where it does`)

## Refuses when

A graph makes a value of the shape a field invariant holds over, and the fields a conjunct of the rule reads are all
written there as literals that make it false. What is proved nowhere is guarded at run time, but a value written out
in full is known now, so the tree is refused at check time instead of at the first run. The refusal is against the
graph, at `nodes/<id>` of the node that makes the value, not against the invariant: the value is what is wrong, and
the invariant is what says so. The message names the invariant, the rule and each field it read as it stands
(`email = ""`, or `note is absent`). A value a graph takes as its input is the caller's, and never refused here.

## Example

```
I005  @features/customers/data/store-and-latest.graph.json#nodes/customer
    the value 'customer' makes contradicts 'A customer is reachable' (@features/customers/domain/a-customer-is-reachable.invariant.json): 'len(name) > 0 && len(email) > 0 && (tier != 'gold' || has(note))' is false where email = ""
    → the value contradicts 'A customer is reachable' (@features/customers/domain/a-customer-is-reachable.invariant.json): len(name) > 0 && len(email) > 0 && (tier != 'gold' || has(note))
```

## Fix

Correct the literal so the rule holds (a non-empty `email`, a `note` on a gold account). If the value is right and
the rule is not, change the invariant's `holds.when`, which the whole tree is then held to.
