# X103

- **Family:** X -- plugin rules, @auth (@wilanis/plugin-auth)
- **Status:** live, since 0.1.0
- **Made in:** `packages/plugin-auth/src/rules.ts`
- **Proved by:** `libraries/access/test/access.test.ts` (`X102 a challenge by a method the settings do not declare; X103 a session write outside the session shape`)

## Refuses when

A call to `@auth/session.port.json#get`, `#set` or `#remove`, from a graph's node or a binding's operation, steps
outside the session shape the `@auth` plugin's `settings.session` names. Three things are judged: a `type` input
that names another shape (at `.../in/type`); a key of a `set`'s `values` the shape does not declare (at
`.../in/values/<key>`); and a key a `remove` drops that the shape does not declare (at `.../in/keys`). A shape marked
`open` declares every key. A session holds what its shape says and nothing else, so a write outside it would store an
attribute no reader is typed for.

## Example

Write a `colour` into the session where the shape declares `theme`:

```
X103  @features/access/data/write-theme.graph.json#nodes/written/in/values/colour
    set writes 'colour', which @access/domain/Session.shape.json does not declare
    → declare the attribute in the session shape, or drop it
```

A `type` naming another shape reads `set names type '@access/domain/Grant.shape.json', but the session shape is
'@access/domain/Session.shape.json'`, with the hint `write "type": "@access/domain/Session.shape.json"`.

## Fix

Declare the attribute in the session shape if the session is meant to hold it, or drop it from the write. A `type`
input is always the session shape's path, as the hint writes it.
