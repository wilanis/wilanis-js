# G029

- **Family:** G -- graphs
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/graph-after.ts`
- **Proved by:** `packages/runtime/test/sabotage-after.test.ts` (`refuses an unknown node, at the entry`)

## Refuses when

A run or a map names a node under `after` that it cannot wait for (RFC 0041). `after` lists nodes of the same graph:
the node starts only once each of them has answered, and its operation is not given their answers. An entry is
refused when it names:

- a node this graph does not have (`after names unknown node 'x'`);
- the node itself (`'x' waits for itself`): it would never start;
- a switch (`after names switch 's', which answers on every branch`). A switch answers whichever way it decides, so a
  node that waits for it starts on every branch. That looks like a wait for a check, but it holds nothing back.

The refusal sits at the entry, `nodes/<id>/after/<index>`.

## Example

In `kept-get`, have `customer` wait for a node that is not there:

```
G029  @features/customers/data/kept-get.graph.json#nodes/customer/after/0
    after names unknown node 'nowhere'
    → name a node of this graph that must answer before 'customer' starts
```

An entry that names a switch is told the node its rule routes to, which runs only where the rule held:

```
G029  @features/customers/data/kept-get.graph.json#nodes/everyLatest/after/0
    after names switch 'isKept', which answers on every branch
    → wait for the node its rule routes to: "after": ["customer"]
```

Where the waiter is itself a node the switch routes to, the hint says it waits for the switch already: `drop 'isKept'
from after: 'customer' already runs only where 'isKept' routes to it`.

## Fix

Name a node of the graph that must answer first. For a switch, name the node its rule routes to: that node runs only
on that branch, so the waiter runs only there too. Drop an entry that names the node itself.
