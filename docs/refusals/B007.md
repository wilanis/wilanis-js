# B007

- **Family:** B -- bindings, profiles and startup
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/project.ts`
- **Proved by:** `packages/runtime/test/sabotage-project.test.ts` (`B007 a startup step giving input to an operation that takes none`, `B007 a startup step reading the request, which nothing has sent yet`, `B007 a startup step reading an undeclared secret`)

## Refuses when

A startup step's `in`, at `startup/<index>/in`, is written as literals and `{{secrets.<key>}}` only, since the step
runs before anything is received, and meets the contract of the operation it fires. Refused: a template that reads
anything but a secret, such as `{{request.body}}`; a secret `project.json → secrets` does not declare; inputs that do
not fit what the operation accepts, such as a missing required field or a wrong type; and any input at all to an
operation that accepts none.

## Example

Give the example's first step, which fires `prepare`, an input:

```
B007  @project.json#startup/0/in
    startup step 0: '@customers/domain/customer.port.json#prepare' takes no input
    → remove in
```

Read the request in it instead:

```
B007  @project.json#startup/0/in
    startup step 0: x: {{request.body}}: a startup step runs before anything is received; only {{secrets.<key>}} may appear
    → write the value, or declare the key under project.json → secrets
```

## Fix

Write the value as a literal, or read it as a secret declared under `project.json → secrets`. For inputs that do not
fit, `wilanis describe <port>` shows what the operation accepts. Remove `in` from a step whose operation takes nothing.
