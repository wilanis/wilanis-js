# X223

- **Family:** X -- plugin rules, @storage-postgres (@wilanis/plugin-storage-postgres)
- **Status:** live, since 0.1.0
- **Made in:** `packages/plugin-storage-postgres/src/rules.ts`
- **Proved by:** `packages/plugin-storage-postgres/test/rules.test.ts` (`X223 a collection name longer than a table name PostgreSQL keeps whole`, `X223 two collections of one connection that fold to one table name`)

## Refuses when

A collection kept over a postgres connection has a name PostgreSQL will not keep as a table, or one it will not keep
apart from another collection of the same connection. The refusal sits at `collections/<name>`, in two forms:

- the name, folded to lower case, is not a letter or an underscore followed by letters, digits or underscores, or is
  longer than 63 characters, the most PostgreSQL keeps of an identifier;
- the name folds to the same lower-case name as a collection seen before it on the same connection. PostgreSQL folds
  an unquoted identifier, so `entriesKept` and `entrieskept` are one table. The later of the two is refused.

Two stores that declare one name with different shapes are @storage's to refuse (X207); this rule refuses what only
the fold makes one.

## Example

Declare `entriesKept` and `entrieskept` in the customers store, over a postgres connection:

```
X223  @features/customers/data/customers.store.json#collections/entrieskept
    'entrieskept' and 'entriesKept' are one table once folded to lower case, and PostgreSQL folds an unquoted name
    → rename one of the two collections
```

A name that is not a table name reads `'<name>' is not a table name this engine can create: a letter or an
underscore, then letters, digits or underscores, at most 63 characters`, with the hint `rename the collection`.

## Fix

Rename the collection, or one of the two that fold together, to a name that is legal and distinct once lower-cased.
Every graph and binding that names the collection must follow the rename, and a collection that already holds rows
keeps them only if the collection records its old name under `was`, so `wilanis migrate` renames the table rather than
dropping it.
