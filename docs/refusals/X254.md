# X254

- **Family:** X -- plugin rules, @schedule (@wilanis/plugin-schedule)
- **Status:** live, since 0.1.0
- **Made in:** `packages/plugin-schedule/src/rules.ts`
- **Proved by:** `packages/runtime/test/sabotage-schedule.test.ts` (`X254 a lease on a connection whose kind keeps none`)

## Refuses when

A startup step that runs `@schedule/scheduler.port.json#run` names a `lease` on a connection whose kind does not
declare `leases`. The lease is where several processes agree which of them fires a
tick, so it must be kept by something that can hold one. The refusal sits at `startup/<index>/in/lease` of
`@project.json`.

## Example

Give the example's run step a lease on the customers API's HTTP connection:

```
X254  @project.json#startup/5/in/lease
    '@connections/customers-api.connection.json' is of kind '@http/http.connection-kind.json', which does not declare leases, so nothing there can keep the scheduler's hold
    → name a connection whose kind declares leases; wilanis ls connection-kind
```

A lease naming no connection document is not X254: the port marks `lease` `"names": "connection"`, so it is the
compiler's [R001](R001.md), `unknown connection '@connections/nope.connection.json'`, at the same `at` (RFC 0037).

## Fix

Name a connection whose kind declares leases, which `wilanis ls connection-kind` shows. A tree that runs one process
may drop the lease, and is not refused for it.

## History

- 0.1.0: introduced.
- 0.1.0: a lease naming no connection is no longer X254 but R001, from the compiler (RFC 0037).
