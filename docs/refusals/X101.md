# X101

- **Family:** X -- plugin rules, @auth (@wilanis/plugin-auth)
- **Status:** live, since 0.1.0
- **Made in:** `packages/plugin-auth/src/rules.ts`
- **Proved by:** `packages/plugin-auth/test/auth.test.ts` (`X101 a session shape that is not a shape`)

## Refuses when

The `@auth` plugin's `settings.session` in `project.json` names something that is not a shape. The session shape is
what a session's attributes are held to: `@auth/session.port.json` reads and writes them, and X103 and X105 judge
every write against it. While it names no shape, neither of those rules can run, so the tree is refused here
instead. A tree that leaves `settings.session` out is not refused.

## Example

Name a shape the access tree does not have:

```
X101  @project.json#plugins/@auth/settings/session
    settings.session names '@access/domain/Nope.shape.json', which is not a shape
    → wilanis ls shape
```

In the example this comes with two C012s on the stores' `scoped` tenant, since a read of
`request.session.attributes.tenant` has no shape left to type it; they go with the same edit.

## Fix

Run `wilanis ls shape` and name the shape the session's attributes follow, usually a core shape in the `domain/` of
the feature that signs callers in (`@access/domain/Session.shape.json` in the example).
