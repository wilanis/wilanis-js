# C009

- **Family:** C -- connections, settings and stores
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/contracts.ts`
- **Proved by:** `packages/runtime/test/sabotage-atomic.test.ts` (`is refused where it says nowhere static to resolve a connection from -- C009`)

## Refuses when

A port operation marked `transactional` accepts neither a `connection` nor a `store` marked `"static": true`. An
atomic graph's one transaction is judged before anything runs, by following the connection each effect goes to,
and those two fields are what the compiler knows how to follow: a connection document, or a store that names one.
A value known only at run time could not be judged. It points at `operations/<name>/accepts` of the port, which in
practice is a plugin's.

## Example

A plugin shipping a transactional operation that accepts only a string:

```
C009  @fake/fake.port.json#operations/write/accepts
    operation 'write' is transactional but accepts no static 'connection' or 'store' to resolve one from
    → accept "connection" (a connection document) or "store" (a store document that names one), marked "static": true
```

## Fix

In the port, accept `connection` or `store` with `"static": true`, as the hint says. If the operation cannot say
where it writes before it runs, it cannot take part in a transaction: drop `transactional`.
