# L015

- **Family:** L -- layers, effects and visibility
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/contracts.ts`
- **Proved by:** `packages/runtime/test/sabotage-listens.test.ts` (`L015 a port read from an input the operation does
  not accept, or one that is not a number`, `L015 an interface read from an input that is not a string`)

## Refuses when

An operation's `listens.port.input` names no field the operation `accepts`, or one whose type is not `number`; or
its `listens.host.input` names no accepted field, or one whose type is not `string`. The startup step that runs
the operation writes the address under `in`, so the input a part is read from must be one the step can write, of
the type the part takes. Each part is its own refusal, at `operations/<name>/listens/port/input` or
`operations/<name>/listens/host/input`. The hint lists the accepted fields of the right type.

## Example

Point `listens.port.input` of `@http/server.port.json`'s `listen` at `route`, a field it does not accept:

```
L015  @http/server.port.json#operations/listen/listens/port/input
    operation 'listen' reads its port from in.route, which is not a field it accepts
    → name a number field this operation accepts: port
```

Pointed at `host`, the message reads `which is string, not number`; `listens.host.input` pointed at `port` reads
`which is number, not string` and the hint lists the string fields, `host`.

## Fix

Name a field of the operation's `accepts` of the part's type, or accept one: a `number` field for the port, a
`string` field for the interface. Drop `input` when the step is not meant to fix that part, and the setting or
the default then decides it.
