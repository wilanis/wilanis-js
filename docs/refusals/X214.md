# X214

- **Family:** X -- plugin rules, @storage (@wilanis/plugin-storage)
- **Status:** live, since 0.1.0
- **Made in:** `packages/plugin-storage/src/scopes.ts`
- **Proved by:** `packages/runtime/test/sabotage-scoping.test.ts` (`X214 a scope written by hand on the site the compiler fills: the M12 demo, refused`); `packages/plugin-storage/test/rules.test.ts` (`X214 a scope over a collection that keeps none: there is no column for it to fill`)

## Refuses when

A call site, in a graph or a binding delegation, writes a `scope` input. A scope is the store's word about who is
calling: a column the collection declares under `scoped`, filled from a read the store binds, which the compiler puts
on every site over that collection. So no document writes one. Over a scoped collection a written scope would
overwrite what the store bound; over an unscoped collection or a view it names a column nothing keeps; on `newKey` it
asks for a scope the operation does not take, since a key is unique across every scope. The refusal sits at
`.../in/scope`, whichever operation it was given to.

## Example

Write the tenant by hand on `kept-get`'s read:

```
X214  @features/customers/data/kept-get.graph.json#nodes/storedCustomer/in/scope
    scope is the store's: 'customers' is scoped by tenant ← {{tenant}} of @customers/data/customers.store.json, and the compiler puts it here
    → drop "scope": to change how 'customers' is scoped, change @customers/data/customers.store.json
```

Over the `everyCustomer` view it reads `'everyCustomer' is a view of 'customers', and a view sees every row`.

## Fix

Drop `scope` from the call. To change how a collection is scoped, change the store's `scoped` and `reads`. To read
across every scope, read a view of the collection, behind the policy the view names.
