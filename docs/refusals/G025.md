# G025

- **Family:** G -- graphs
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/graph-nodes.ts`
- **Proved by:** `packages/runtime/test/sabotage-catch.test.ts` (`refuses it, where the catch names the node`)

## Refuses when

A switch's `catch` names a node where a field invariant is guarded: a site that makes a value of the invariant's shape
where the checker could not prove the rule, so the compiler lowers a guard there. The guard moves the node aside to
`<id>:made` and answers the value from `<id>` once the rule held, so a catch of `<id>` would catch the guard's answer,
never the effect, and the effect's fault would go uncaught. Which sites are guarded is `guardsOf`'s answer, the one
the lowering writes guards from. The refusal sits at `nodes/<switch>/catch/<caught>`.

## Example

Add a switch to `kept-list` that catches `customers`, the `#find` whose list the customer invariant is guarded at:

```
G025  @features/customers/data/kept-list.graph.json#nodes/anyKept/catch/customers
    catches 'customers', where an invariant is guarded: the guard moves it aside, and its fault would go uncaught
    → catch a node the invariant is not checked at, or prove the rule where 'customers' is made, so no guard is lowered there
```

## Fix

Catch a node the invariant is not checked at, or prove the rule where the value is made, from routing or literals that
already establish it, so no guard is lowered there and the catch reaches the effect. Routing a fault to a guarded node
is allowed; only catching one is refused.
