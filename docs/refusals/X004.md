# X004

- **Family:** X -- plugin rules, @http (@wilanis/plugin-http)
- **Status:** live, since 0.1.0
- **Made in:** `packages/plugin-http/src/rules.ts`
- **Proved by:** `packages/plugin-http/test/limits.test.ts` (`refuses a deadline or a bound that is not a whole number of 1 or more, wherever it is written`; `refuses a deadline longer than a Node timer can wait, and takes one at the bound`)

## Refuses when

A deadline or a body bound could never be met: `deadlineMs` (the most a run may take, in milliseconds) or
`maxBodyBytes` (the most a body may weigh, in bytes) is not a whole number of 1 or more. Both are judged in the
`@http` plugin's settings (`@project.json`, at `plugins/@http/settings/<name>`) and in every http trigger's
`settings`; an http connection's `settings/maxBodyBytes`, the bound on an upstream's answer, is judged too. A zero, a
negative number or a fraction would cancel every run or refuse every body.

A `deadlineMs` is also at most 2147483647 (2^31 - 1 ms, about 24.8 days). The deadline is a Node timer, and Node
fires a timer set longer than that after 1 ms, so a deadline of 30 days would cancel every run at once
(`packages/plugin-http/test/timer-bound.test.ts` shows it).

## Example

Give the get-customer route a deadline of zero:

```
X004  @features/customers/edge/get-customer.trigger.json#settings/deadlineMs
    deadlineMs is 0; it is the most a run may take, in milliseconds, a whole number of 1 or more
    → set it to 1 or more, or drop it for no limit
```

A `maxBodyBytes` of `1.5` on the customers API connection is refused the same way, at
`@connections/customers-api.connection.json#settings/maxBodyBytes`. A deadline of 30 days reads:

```
X004  @features/customers/edge/get-customer.trigger.json#settings/deadlineMs
    deadlineMs is 2592000000; it is the most a run may take, in milliseconds, and a Node timer waits at most 2147483647 ms (about 24.8 days): a longer one fires after 1 ms, so every run would be cancelled at once
    → set it to 2147483647 or less, or drop it for no limit
```

## Fix

Write a whole number of 1 or more (for a deadline, at most 2147483647), or delete the member to have no limit there. A route's own value takes the place
of the plugin's, so a limit meant for every route belongs in the plugin's settings.

## History

- 0.1.0: introduced.
- 0.1.0: a `deadlineMs` above 2147483647 is refused, since Node fires a longer timer after 1 ms (#924).
