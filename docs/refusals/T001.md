# T001

- **Family:** T -- triggers
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/triggers.ts`
- **Proved by:** `packages/runtime/test/sabotage-unproved.test.ts` (`T001 a type setting written as anything but a string`)

## Refuses when

A trigger's `settings` do not fit the settings its kind declares: a field of the wrong type, a required one missing,
a value outside the kind's enum. The refusal sits at `settings` and its message is the mismatch. A setting the kind
types as `type` (a route's `body`, say) is a shape reference, so it is judged a second time on its own, at
`settings/<name>`: it must be a string naming a shape, and that shape must be in the edge layer.

## Example

Write the list route's `body` setting as an object rather than a shape path, and it is refused twice, once against
the kind's settings and once as a type reference:

```
T001  @features/customers/edge/list-customers.trigger.json#settings
    settings: field 'body': {not: "a string"} is not a type reference
    → wilanis describe @http/http.trigger-kind.json
T001  @features/customers/edge/list-customers.trigger.json#settings/body
    settings.body is a type reference, written as a string
    → write the shape path as a string, as in @std/text
```

## Fix

Run `wilanis describe` on the kind the hint names and write the settings it declares. A type setting is a string
naming an edge shape, as in `"body": "@customers/edge/ListRequest.shape.json"`.
