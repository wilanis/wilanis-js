# B008

- **Family:** B -- bindings, profiles and startup
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/project.ts`
- **Proved by:** `packages/runtime/test/sabotage-project.test.ts` (`B008 a startup step whose bound graph reads the request`)

## Refuses when

B007 judges what a startup step writes; B008 judges what it reaches. Under each profile the checker walks the bindings
and graphs the step's operation leads to, and each document among them that reads `request.*` (through a resolver a
data graph, a binding or a store reads) is refused against the step, at `startup/<index>/run`, since nothing has been
received when a step runs. The message names the document, the path it reads and the profile.

## Example

Have the first step fire `register`, whose data graph stamps the caller's user agent under `live` and whose store is
scoped by a session attribute under `local` (a B007 comes with it, since the step leaves out `name`):

```
B008  @project.json#startup/0/run
    startup step 0: @features/customers/data/create-row.graph.json reads request.headers.user-agent, but a startup step runs before anything is received (profile 'live')
    → fire this operation from a trigger, or bind the port to a graph that reads no request
```

## Fix

A step is for what a tree needs before it serves: opening, preparing, checking that something answers. An operation
that reads the caller belongs behind a trigger. If the step is right, bind its port, under each profile the refusals
name, to a graph that reads no request.
