- **Proved by:** `packages/runtime/test/sabotage-storage.test.ts` (`X211 a patch that changes the key: a key identifies, so it is never patched`), (`X211 a patch that changes a field the shape does not have`), (`X211 a patch whose value the field would not accept`)

## Refuses when

A `patch` call's `changes` changes the collection's key, names a field the collection's shape does not have, or gives
a literal the field would not accept. A `changes` written as one read is judged whole, against the shape with every
field optional, since a patch is exactly that partial write. The `at` is `.../in/changes/<field>`, or
`.../in/changes` for the whole read.

## Example

Turn `keep-customer`'s write into a patch, and make it change the key:

```
X211  @features/customers/data/keep-customer.graph.json#nodes/stored/in/changes/id
    'id' identifies the record, and a patch never changes it
    → a key identifies; it is never patched
```

A field the shape lacks reads `'nope' is not a field of @customers/domain/Customer.shape.json (fields: ...)`, and a
value of the wrong type `where a patch changes 'name', name: expected string`.

## Fix

Drop the key from `changes`: a record under another key is a new record, written with `put`, and the old one removed.
Otherwise name a field the message lists, with a value of the type the hint names.
