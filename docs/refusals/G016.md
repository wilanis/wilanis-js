# G016

- **Family:** G -- graphs
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/inputs.ts`
- **Proved by:** `packages/runtime/test/example.test.ts` (`G016 a refuse node whose message reads the password the credential marks secret`)

## Refuses when

A refusing node's `message` reads a field marked secret. A refusal's message is said to the caller, so nothing in it
may reach a secret. What is secret is the walk the report redacts by (`secretPaths`), taken over the type the read
starts from, so a read of a secret field, or of anything below one, is refused. The refusal sits at the node's
`nodes/<id>/in/message`.

## Example

Have the access tree's `sign-in-customer` graph say the password back when it rejects a sign-in:

```
G016  @features/access/domain/sign-in-customer.graph.json#nodes/rejected/in/message
    the message reads 'in.password', a field marked secret
    → a refusal's message is said to the caller; say it without the secret
```

## Fix

Say it without the secret: `no account {{in.username}} with that password`. The run's report keeps what the caller
sent, redacted; the caller is told only the message.
