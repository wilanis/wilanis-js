# G017

- **Family:** G -- graphs
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/attempts.ts`
- **Proved by:** `packages/runtime/test/sabotage-attempts.test.ts` (`G017 a retry over a pure operation, or over a binding whose graph reaches no effect`)

## Refuses when

A `retry` is written over something that cannot fail transiently. It takes two forms. On a data graph's node, or a
binding operation that delegates, the call is a native operation marked `pure`: `retry over '<op>', which is pure`.
On a binding operation that runs a graph, or that delegates to a domain operation, the walk below it reaches no effect
under any profile that binds the binding: `retry over '<graph>', which reaches no effect`. Nothing there talks to
anything outside the process, so a failure is a bug and trying again repeats it. The refusal sits at
`nodes/<id>/retry` or `operations/<name>/retry`.

## Example

Retry `get-row`'s `customer` node, which only makes a value, and then the greeting binding, whose graph is pure:

```
G017  @features/customers/data/get-row.graph.json#nodes/customer/retry
    retry over '@std/object.port.json#make', which is pure
    → nothing here can fail transiently; delete retry
G017  @features/hello/data/greeting.binding.json#operations/hello/retry
    retry over '@features/hello/domain/greet.graph.json', which reaches no effect
    → nothing here can fail transiently; delete retry
```

## Fix

Delete `retry`. If it was meant for an effect nearby, write it on the node or binding operation that runs that effect.
