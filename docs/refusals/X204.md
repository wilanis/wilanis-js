# X204

- **Family:** X -- plugin rules, @storage (@wilanis/plugin-storage)
- **Status:** live, since 0.1.0
- **Made in:** `packages/plugin-storage/src/rules.ts`
- **Proved by:** `packages/plugin-storage/test/rules.test.ts` (`X204 a collection the store does not declare, naming the ones it does`)

## Refuses when

A call to a `@storage` operation, from a data graph's node or a binding's delegation, names a `collection` the named
store does not declare. It sits at `.../in/collection`, and its message lists the collections the store does declare.

A `store` that is no store document of this tree is not X204: it is the compiler's [R001](R001.md), at
`.../in/store`, since `@storage` marks that field `"names": "store"` and the compiler judges every marked literal
(RFC 0037).

## Example

Point `kept-list`'s find at a collection the customers store does not have:

```
X204  @features/customers/data/kept-list.graph.json#nodes/customers/in/collection
    '@customers/data/customers.store.json' declares no collection 'nope' (collections: customers, latest, everyCustomer)
    → wilanis describe @customers/data/customers.store.json
```

The node answers `unknown`, so what reads it is refused too (here G010 on `out/from`); those go with the same edit.

## Fix

Name a collection the message lists. A new collection is declared in the store document, never at the call site.

## History

- 0.1.0: introduced.
- 0.1.0: a store the tree does not hold is no longer X204 but R001, from the compiler (RFC 0037).
