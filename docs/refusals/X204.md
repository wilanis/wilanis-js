# X204

- **Family:** X -- plugin rules, @storage (@wilanis/plugin-storage)
- **Status:** live, since 0.1.0
- **Made in:** `packages/plugin-storage/src/rules.ts`
- **Proved by:** `packages/plugin-storage/test/rules.test.ts` (`X204 a store this tree does not hold, pointing at the input that named it`), (`X204 a collection the store does not declare, naming the ones it does`)

## Refuses when

A call to a `@storage` operation, from a data graph's node or a binding's delegation, names a `store` that is no store
document of this tree, or a `collection` the named store does not declare. The first sits at `.../in/store`, the
second at `.../in/collection`, and its message lists the collections the store does declare.

## Example

Point `kept-list`'s find at a collection the customers store does not have:

```
X204  @features/customers/data/kept-list.graph.json#nodes/customers/in/collection
    '@customers/data/customers.store.json' declares no collection 'nope' (collections: customers, latest, everyCustomer)
    → wilanis describe @customers/data/customers.store.json
```

A store that is not there reads `'@customers/data/nope.store.json' is not a store of this tree`, with the hint
`wilanis ls store`. Either way the node answers `unknown`, so what reads it is refused too (here G010 on `out/from`);
those go with the same edit.

## Fix

Name a store `wilanis ls store` lists and a collection the message lists. A new collection is declared in the store
document, never at the call site.
