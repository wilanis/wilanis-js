# D014

- **Family:** D -- documents
- **Status:** live, since 0.1.0
- **Made in:** `packages/core/src/ir-version.ts`
- **Proved by:** `packages/runtime/test/sabotage-ir-version.test.ts` (`D014 a tree whose customers feature names v2
  and the rest v1, said once, at the project`, `D014 names each version, how many documents name it, and one of
  them`, `none where the alias stands beside the published URL: the alias is the version this runtime reads`),
  `packages/core/test/ir-version.test.ts` (`D013 a plugin whose docs/ are of a version this runtime does not read,
  and the tree mixes versions`, `D013 at every document of a tree wholly of a version this runtime does not read, and
  no D014`)

## Refuses when

The documents a load reads name more than one IR version between them (RFC 0008). A version belongs to the tree, not
to a document, because the checker's rules span kinds: a graph is judged against the port it runs and the shapes it
passes, and a rule that had to ask which version each side was written in would be written twice. The documents
counted are the ones D013 reads -- the tree's, its includes', and the `docs/` of the plugins it names -- and the alias
counts as the version this runtime reads, so a tree writing `@wilanis/graph.schema.json` beside the v1 URL mixes
nothing.

A runtime reads one version, so a tree that mixes two always holds documents of a version it does not read, and D013
refuses each of them beside this one: D013 says which documents this runtime cannot read, D014 that the tree is not
one version. A tree wholly of another version is one version, and has D013 at every document and no D014. The
refusal is said once, at `project.json` with no `at`, and names each version, how many documents name it, and one of
them. Like D013 it is judged before any other rule, and a tree it refuses is read no further.

## Example

Rewrite every document of the customers feature from `main` to the tag `schemas-v2`, and leave the rest at v1. Each of
the 85 is refused as D013, and the tree once:

```
D014  project.json
    the documents of this tree name more than one IR version: v1 (137, connections/customers-api.connection.json among them), v2 (85, features/customers/data/create-row.graph.json among them)
    → a tree is one version: upgrade the rest to the newer one, or rewrite every $schema against v1, under https://raw.githubusercontent.com/wilanis/wilanis-js/main/packages/core/schemas (docs/rfcs/0008-ir-versioning.md)
```

## Fix

Move the tree to one version. Where some documents stand apart from the rest, copied in from a tree of a newer
version or the first of a tree being moved, either rewrite each against the version the rest are in, its `$schema`
under the base the hint names, or upgrade the rest to theirs with a runtime that reads it. The D013s beside this name
the documents this runtime cannot read.
