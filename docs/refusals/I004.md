# I004

- **Family:** I -- invariants
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/invariant-holds.ts`
- **Proved by:** `packages/runtime/test/sabotage-invariants.test.ts` (`I004 a rule whose root is not a field of the shape`, `I004 a rule that does not type against the fields it names`, `I004 a rule that does not parse, and one that is not a boolean`)

## Refuses when

A field invariant's `holds.when` is not a boolean expression over the shape's fields. The rule's roots are the
fields of the shape `holds.on` names, an optional field read as optional; the refusal carries the expression
checker's own message when the rule does not parse or names something that is not a field, or does not type
(`email > 3`), and says `'<when>' is <kind>, not boolean` when it types to something else. It sits at `holds/when`,
and the hint lists the fields. A rule that fails here is not used, so no site is judged against it.

## Example

```
I004  @features/customers/domain/a-customer-is-reachable.invariant.json#holds/when
    'quantity' is not an input of this node (inputs: id, name, email, tier, registrar, active, note)
    → the roots are the shape's fields: id, name, email, tier, registrar, active, note
```

The words "of this node" are the expression checker's, which a switch's rules share; here the inputs it names are the
shape's fields.

## Fix

Write the rule over the fields the hint lists, with the operators the expression language has (`wilanis describe`
on the shape gives each field's type), and make the whole a comparison or a conjunction that comes out boolean:
`len(email) > 0`, not `len(email)`.
