# T004

- **Family:** T -- triggers
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/triggers.ts`
- **Proved by:** `packages/runtime/test/sabotage-reads.test.ts` (`T004 a resolver reading request.* under a kind that hands none`)

## Refuses when

Something a trigger reaches reads a `request.*` path the trigger's kind does not hand. The reads are the resolvers a
data graph, a binding or a store takes under `reads`, gathered through what the trigger fires and through each of its
policies' decisions, profile by profile, since which binding meets an operation decides which graph runs. P002 judges
a resolver against every kind; this is the same read judged against the one kind that reaches it here. The refusal
sits at the trigger's `kind`, names the document that reads, and names the profile when the read is one profile's.

## Example

Have `list-rows` send the user agent through the request resolvers. The digest, a command-line trigger, reaches that
graph under the live profile, and a command line hands no headers:

```
T004  @features/customers/edge/digest.trigger.json#kind
    @features/customers/data/list-rows.graph.json reads request.headers.user-agent but trigger kind '@cli/cli.trigger-kind.json' hands no such value (profile 'live')
    → fire this operation from a kind that hands it, or bind the port differently under a profile
```

## Fix

Fire the operation from a kind that hands the value, or bind the port, under the profile named, to a graph that does
not read it. A graph that reads a header is not one to share between a route and a command.
