# X241

- **Family:** X -- plugin rules, @storage-mysql (@wilanis/plugin-storage-mysql)
- **Status:** live, since 0.1.0
- **Made in:** `packages/plugin-storage-mysql/src/rules.ts`
- **Proved by:** `packages/plugin-storage-mysql/test/rules.test.ts` (`X241 a blob field, which this engine has no column for`)

## Refuses when

A store kept over a connection of kind `@storage-mysql/mysql.connection-kind.json` declares a collection whose
shape has a field of type `blob`. This engine gives a string a `TEXT` or `VARCHAR` column, a number `DOUBLE`, a
boolean a `TINYINT(1)` that is 0 or 1 and anything else `JSON`; a blob has none, because its bytes live in the blob
registry and a record holds only a handle. The refusal sits at `collections/<name>/of`, once per blob field of the
shape. The same store kept over another engine is not this plugin's to judge.

## Example

Add a `file` field of type `blob` to the shape the customers store keeps, over a mysql connection:

```
X241  @features/customers/data/customers.store.json#collections/entries/of
    'file' is a blob, and this engine has no column for one: the bytes live in the blob registry
    → store the handle's id as a string, and read the bytes through @blob
```

## Fix

Change the field to a `string` that holds the handle's id, and read or write the bytes through the `@blob`
operations, which stream them in and out of the registry. If the record does not need the file at all, drop the
field from the shape.
