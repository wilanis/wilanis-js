# X401

- **Family:** X -- plugin rules, @queue (@wilanis/plugin-queue)
- **Status:** live, since 0.1.0
- **Made in:** `packages/plugin-queue/src/rules.ts`
- **Proved by:** `packages/plugin-queue/test/rules.test.ts` (`X401: a setting a worker cannot act on`, from `an outcome that is not ack, retry or dead` to `the consume step's concurrency of none`)

## Refuses when

A queue trigger, or the step that consumes the queues, says something the worker cannot act on. A value of a
trigger's `settings.outcomes` is one of the three words a broker acts on -- `ack`, `retry`, `dead` -- and is refused at
`settings/outcomes/<reason>` otherwise; the kind's schema types the table's values as strings, so the words are the
plugin's to judge. A `maxAttempts` counts deliveries, the first among them, so it is a whole number of 1 or more. A
`backoffMs` is the wait before a second delivery, a whole number of milliseconds of 0 or more. In `project.json`, a
step running `@queue/worker.port.json#consume` gives a `concurrency` that is a whole number of 1 or more, refused at
`startup/<index>/in/concurrency`.

## Example

Map the removals trigger's `upstream` to a word no broker knows:

```
X401  @features/customers/edge/removals.trigger.json#settings/outcomes/upstream
    outcomes maps 'upstream' to "later", and a broker acts on ack, retry or dead only
    → an outcome is ack, retry or dead
```

A `maxAttempts` of 0 reads `maxAttempts is 0; it counts deliveries, the first among them, so it is a whole number of
1 or more`.

## Fix

Follow the hint for the setting `at` names: map the reason to `ack` (the work is done or not worth doing), `retry`
(deliver it again later) or `dead` (park it); give `maxAttempts` and `concurrency` a whole number of 1 or more and
`backoffMs` one of 0 or more, or drop any of the three for its default (5, 1 and 1000).
