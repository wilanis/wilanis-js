# X401

- **Family:** X -- plugin rules, @queue (@wilanis/plugin-queue)
- **Status:** live, since 0.1.0
- **Made in:** `packages/plugin-queue/src/rules.ts`
- **Proved by:** `packages/plugin-queue/test/rules.test.ts` (`X401: a setting a worker cannot act on`, from `an outcome that is not ack, retry or dead` to `the consume step's concurrency of none`); `packages/runtime/test/sabotage-queue.test.ts` (`X401 an outcome that is not ack, retry or dead, and a maxAttempts below one`, `X401 a deadline of none, of part of a millisecond, or longer than a Node timer waits`)

## Refuses when

A queue trigger, or the step that consumes the queues, says something the worker cannot act on. A value of a
trigger's `settings.outcomes` is one of the three words a broker acts on -- `ack`, `retry`, `dead` -- and is refused at
`settings/outcomes/<reason>` otherwise; the kind's schema types the table's values as strings, so the words are the
plugin's to judge. A `maxAttempts` counts deliveries, the first among them, so it is a whole number of 1 or more. A
`backoffMs` is the wait before a second delivery, a whole number of milliseconds of 0 or more. A `deadlineMs` is the
most one delivery's run may take, a whole number of milliseconds of 1 or more and at most 2147483647 (2^31 - 1 ms,
about 24.8 days): the deadline is a Node timer, and Node fires a timer set longer than that after 1 ms, so every run
would be cancelled at once. In `project.json`, a step running `@queue/worker.port.json#consume` gives a
`concurrency` that is a whole number of 1 or more, refused at `startup/<index>/in/concurrency`.

## Example

Map the removals trigger's `upstream` to a word no broker knows:

```
X401  @features/customers/edge/remove-queued.trigger.json#settings/outcomes/upstream
    outcomes maps 'upstream' to "later", and a broker acts on ack, retry or dead only
    → an outcome is ack, retry or dead
```

A `maxAttempts` of 0 reads `maxAttempts is 0; it counts deliveries, the first among them, so it is a whole number of
1 or more`.

Give the same trigger a deadline of nothing:

```
X401  @features/customers/edge/remove-queued.trigger.json#settings/deadlineMs
    deadlineMs is 0; it is the most one delivery's run may take, so it is a whole number of milliseconds, 1 or more
    → set it to 1 or more, or drop it for no deadline
```

A deadline longer than a Node timer can wait reads:

```
X401  @features/customers/edge/remove-queued.trigger.json#settings/deadlineMs
    deadlineMs is 3000000000; it is the most one delivery's run may take, and a Node timer waits at most 2147483647 ms (about 24.8 days): a longer one fires after 1 ms, so every run would be cancelled at once
    → set it to 2147483647 or less, or drop it for no deadline
```

## Fix

Follow the hint for the setting `at` names: map the reason to `ack` (the work is done or not worth doing), `retry`
(deliver it again later) or `dead` (park it); give `maxAttempts` and `concurrency` a whole number of 1 or more and
`backoffMs` one of 0 or more, or drop any of the three for its default (5, 1 and 1000); give `deadlineMs` a whole
number from 1 to 2147483647, or drop it for no deadline.

## History

- 0.1.0: introduced.
- 0.1.0: a queue trigger's `deadlineMs` is judged too: a whole number from 1 to 2147483647 (RFC 0044, #983).
