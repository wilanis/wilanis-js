# B009

- **Family:** B -- bindings, profiles and startup
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/required.ts`
- **Proved by:** `packages/runtime/test/required-binding.test.ts` (`B009 when it reads the request, since the plugin fires it with none judged`), `packages/runtime/test/sabotage-project.test.ts` (`B009 and B010 a binding of the guard's memory that reads the request, or ends the run on purpose`)

## Refuses when

A port a plugin requires (RFC 0005), such as `@auth/state.port.json`, is fired by the plugin from its own code, the
guard's among it, before any policy has judged the request. Its binding reads nothing of the request. Two forms: the
binding declares `reads` at all, refused at `reads`; and, under each profile, a document the port's operations reach
reads `request.*`, refused on that document with no `at`, naming the operation, the path read and the profile.

## Example

Give the example's binding of `@auth/state.port.json` a `reads` entry for the caller's user agent (L005 and P005 come
with it, since the state feature does not depend on customers and nothing reads the entry):

```
B009  @features/state/data/auth-files.binding.json#reads
    binding of '@auth/state.port.json' declares reads, but @auth fires it with no request judged
    → remove reads; an operation of a port a plugin requires reads only its in
```

Where the read is reached, the test's `@keep` plugin shows the second form: `@keep/memory.port.json#get reaches
@features/keeping/data/keep-files.binding.json, which reads request.headers.user-agent, but @keep fires it with no
request judged (profile '<name>')`, with the same hint.

## Fix

Remove `reads` from the binding, and whatever reads the request beneath it. An operation of a required port reads only
its `in`, which the plugin gives it.
