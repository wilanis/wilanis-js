# X403

- **Family:** X -- plugin rules, @queue (@wilanis/plugin-queue)
- **Status:** live, since 0.1.0
- **Made in:** `packages/plugin-queue/src/publishes.ts`
- **Proved by:** `packages/plugin-queue/test/rules.test.ts` (`X403: a publish of what the consuming trigger does not accept`: `a shape of another name and fields: the refusal names the trigger and the shape it consumes`)

## Refuses when

A graph node or a binding operation runs `@queue/queue.port.json#publish` with a literal `connection` and `queue` that a
queue trigger of the same tree also receives from, and the type its `type` names is not assignable to the trigger's
`settings.message`. The message would arrive and be judged against a shape it does not have. The refusal sits at
`nodes/<id>/in/type` of the graph, or `operations/<name>/in/type` of the binding, and names the trigger. A queue no
trigger of this tree consumes is not judged: another tree may consume it.

## Example

Publish a batch of ids on the queue that consumes one id at a time:

```
X403  @features/customers/data/publish-removal.graph.json#nodes/published/in/type
    publishes '@features/customers/edge/Batch.shape.json' on queue 'removals' of '@connections/jobs.connection.json', which @features/customers/edge/removals.trigger.json consumes as '@features/customers/edge/IdRequest.shape.json': missing required field 'id'
    → publish the shape the trigger consumes: @features/customers/edge/IdRequest.shape.json, or name another queue
```

## Fix

Publish the shape the trigger consumes, which the hint names, with a `message` of that shape; or publish on another
queue, and give that queue a trigger of its own that consumes what is published there.
