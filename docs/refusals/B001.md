# B001

- **Family:** B -- bindings, profiles and startup
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/bindings.ts`
- **Proved by:** `packages/runtime/test/sabotage-unproved.test.ts` (`B001 a port operation no binding meets`)

## Refuses when

A binding meets every operation of the domain port it implements, and nothing else. Two forms: an operation of the
port has no entry under the binding's `operations` (at `operations`, `operation '<name>' of '<port>' is not bound`),
or the binding names an operation the port does not declare (at `operations/<name>`, `'<name>' is not an operation
of '<port>' (<its operations>)`). The port is the contract a trigger fires against; an operation left unmet would
leave a run with nothing to do, and an entry the port does not declare is a typo or dead code.

## Example

Add a `farewell` operation to the hello feature's greeting port, with no binding for it:

```
B001  @features/hello/data/greeting.binding.json#operations
    operation 'farewell' of '@features/hello/domain/greeting.port.json' is not bound
    → add 'farewell' under operations in the binding, or wilanis new binding <feature>/<name> --port @features/hello/domain/greeting.port.json
```

The other way round, a binding entry for an operation the port lacks:

```
B001  @features/hello/data/greeting.binding.json#operations/farewell
    'farewell' is not an operation of '@features/hello/domain/greeting.port.json' (hello)
    → wilanis describe @features/hello/domain/greeting.port.json lists its operations
```

## Fix

For an unbound operation, add it under the binding's `operations`, met by a data graph (`graph`) or a delegation
(`run`); `wilanis new binding` writes an entry for every operation of the port. For an entry the port lacks, correct
its name to one the message lists, or remove it. If the operation should exist, declare it on the port, and every
other binding of that port must then meet it too.
