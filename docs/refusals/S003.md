# S003

- **Family:** S -- scenarios
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/scenarios.ts`
- **Proved by:** `packages/runtime/test/sabotage-limits.test.ts` (`refuses a node the scenario did not stub, at cancelAt`)

## Refuses when

A scenario's `cancelAt` is not one of the keys under its `stubs`. The replay aborts the run's signal where that stub
would have answered, so a path the scenario never stubbed is one the replay never reaches, and nothing would be
cancelled. The refusal sits at `cancelAt`.

## Example

```
S003  @scenarios/cancelled.scenario.json#cancelAt
    cancelAt names 'nope', which is not a stubbed effect of this scenario
    → cancelAt names a stubbed effect: one of the keys under stubs
```

## Fix

Set `cancelAt` to the key of the stubbed effect the run should be cancelled at (a node path such as `op.asked`),
or add a stub under that key if the effect was meant to be stubbed and was not.
