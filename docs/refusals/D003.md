# D003

- **Family:** D -- documents
- **Status:** live, since 0.1.0
- **Made in:** `packages/core/src/documents.ts`, `packages/core/src/load.ts`
- **Proved by:** `packages/runtime/test/sabotage-unproved.test.ts` (`D003 the project document somewhere other than the root`,
  `D003 an answers document under any name but answers.json`, `D003 an answers document at the top of scenarios/,
  where no scenario finds it`)

## Refuses when

A document of a kind with one fixed place is somewhere else. A tree has one project document, `project.json` at its
root, each feature one manifest, `features/<name>/feature.json`, and each recorded directory one answers document,
`answers.json` at its top (RFC 0036). Four forms: a project document anywhere but the root; a feature document
anywhere but its feature's `feature.json`; an answers document under another name, or at the top of `scenarios/`,
where no scenario finds it; and a `project.json` at the root whose `$schema` names another kind. There is no `at`.

## Example

Plant a second project document inside a feature:

```
D003  features/hello/elsewhere.json
    the project document is project.json at the root
    → move it to project.json, or change its $schema to the kind this file is
```

## Fix

Move the document to its one place, as the hint says (for an answers document: `answers.json` in the recorded
directory below `scenarios/` it sits in, else `scenarios/rehearsed/answers.json`), or, when the file was meant to be another kind, correct its
`$schema`. A tree never holds two project documents: fold what the second one says into `project.json`.

## History

- 0.1.0: introduced. Before the release, it came to hold an answers document to its one name (RFC 0036).
