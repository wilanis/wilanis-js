# G014

- **Family:** G -- graphs
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/atomic.ts`
- **Proved by:** `packages/runtime/test/sabotage-atomic.test.ts` (`is refused where a map below it collects the failures -- G014`)

## Refuses when

A `map` node with `"onItemFailure": "collect"` sits inside an atomic graph, or inside a graph an atomic graph reaches
through its bindings. A failed element has already ended the transaction, so collecting its failure would leave the
run done and commit what the element never wrote. The rule is judged over every profile's walk below each atomic
graph, and a map is refused once for each atomic graph that reaches it, the message naming that graph. The refusal
sits at the map's `nodes/<id>/onItemFailure`.

## Example

Add a collecting `map` to `store-and-latest`, which is atomic and which the atomic `register-all` reaches:

```
G014  @features/customers/data/store-and-latest.graph.json#nodes/each/onItemFailure
    map 'each' collects failures inside atomic graph '@features/customers/data/store-and-latest.graph.json', whose transaction a failed element ends
    → use "fail", or take the map out of the atomic graph
G014  @features/customers/data/store-and-latest.graph.json#nodes/each/onItemFailure
    map 'each' collects failures inside atomic graph '@features/customers/domain/register-all.graph.json', whose transaction a failed element ends
    → use "fail", or take the map out of the atomic graph
```

## Fix

Set `onItemFailure` to `"fail"`, so one failed element fails the map and the transaction rolls back whole. If the
elements are meant to succeed or fail one by one, the map does not belong in a transaction: move it into a graph no
atomic graph reaches, or drop `atomic` from the graph that says it.
