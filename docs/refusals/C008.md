# C008

- **Family:** C -- connections, settings and stores
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/stores.ts`
- **Proved by:** `packages/runtime/test/sabotage-storage.test.ts` (`C008 a constraint over a field an engine holds no value of: bytes, a shape or a list`)

## Refuses when

A `unique` or `refs` entry names a field whose type is a `blob`, a shape or a list. A blob's bytes live in the blob
registry, and a shape or a list is not one value an engine can index, so none of them can be constrained. It points
where the constraint is written. A default on such a field is judged by C004, not here.

## Example

Plant a collection with a `string[]` field and make it unique:

```
C008  @features/customers/data/customers.store.json#collections/uploads/unique/0
    'tags' is string[], and a constraint names a value an engine can hold: a string, a number or a boolean
    → wilanis describe @connections/customers.connection.json
```

## Fix

Constrain a string, number or boolean field instead, or drop the constraint. If uniqueness over the list's elements
is what is meant, keep them as records of a collection of their own.
