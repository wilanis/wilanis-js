# C008

- **Family:** C -- connections, settings and stores
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/stores.ts`, and `packages/compiler/src/check/store-engines.ts` for what it
  reads off the engine's kind
- **Proved by:** `packages/runtime/test/sabotage-storage.test.ts` (`C008 a constraint over bytes, which no engine holds; a list is for the kind of its engine to judge, and memory constrains one`),
  `packages/plugin-storage/test/capabilities.test.ts` (`C008 the same unique over a kind constraining strings alone, naming the class and the list`, `C008 refs over a kind that enforces none, where memory, which does, passes them`)

## Refuses when

A `unique` or `refs` entry asks for a constraint the engine behind the store cannot keep. Some of that is true of
every engine, and is judged by the field's type: a blob's bytes live in the blob registry, so neither constraint
names a `blob`, and a reference holds one value, so a `refs` entry never names a shape or a list.

The rest is the engine's, and is read from the `capabilities` its storage connection kind declares (RFC 0022), for
the connection the store names and for each profile's stand-in for it:

- a `unique` entry names a field whose class (`string`, `number`, `boolean`, `shape`, `list` or `unknown`) is not in
  the kind's `capabilities.unique`; it points at the field within the entry;
- a collection declares `refs` over a kind whose `capabilities.refs` is false; it points at the reference.

A default on such a field is judged by C004, not here.

## Example

Over a connection whose kind constrains `unique` over strings alone, make a shape field part of a unique:

```
C008  @features/customers/data/customers.store.json#collections/customers/unique/0/1
    'wanted' is a shape, and @connections/records.connection.json keeps no unique constraint over one
    → 'wanted' is a shape; @narrow-engine/narrow.connection-kind.json constrains unique over string
```

Declare a reference over a kind that does not enforce them:

```
C008  @features/customers/data/customers.store.json#collections/customers/refs/note
    'note' refers to customers, and @connections/records.connection.json enforces no reference
    → @narrow-engine/narrow.connection-kind.json does not enforce refs; check the target with a get, or move the store to a connection that does
```

## Fix

Constrain a field of a class the kind lists, or drop the constraint; `wilanis describe` on the connection kind shows
its `capabilities`. Where the engine enforces no reference, read the target with a `get` before the write, or keep
the store on a connection whose kind does. If uniqueness over a list's elements is what is meant, keep them as
records of a collection of their own.

## History

- 0.1.0: introduced.
- 0.1.0: reads the engine's `capabilities` (RFC 0022): a `unique` over a shape or a list is refused where the kind
  does not constrain that class, not everywhere, and a `refs` over a kind that does not enforce them is refused.
