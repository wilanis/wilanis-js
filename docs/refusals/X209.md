# X209

- **Family:** X -- plugin rules, @storage (@wilanis/plugin-storage)
- **Status:** live, since 0.1.0
- **Made in:** `packages/plugin-storage/src/filters.ts`
- **Proved by:** `packages/plugin-storage/test/rules.test.ts` (`X209 a literal the field would not accept`), (`X209 a read of the graph in, typed by the shape the graph declares`)

## Refuses when

A value a call's `where` tests a field with is one that field would not accept: a literal of the wrong type, or a
read of the graph's `in` whose type does not fit. What each operator compares with is the field's own type, a list
of it for `in` and `notIn`, a boolean for `has`, and text for `contains` and `startsWith`. A read of an earlier node's
answer is left unjudged, since its type is the graph checker's table and not a document the plugin can see. The `at`
is the path of the value inside `where`, with the operator when one is written (`.../in/where/email/contains`).

## Example

Filter `kept-list`'s find by an email that is a number:

```
X209  @features/customers/data/kept-list.graph.json#nodes/customers/in/where/email
    email: expected string
    → email is string
```

## Fix

Give a value of the type the hint names, or read one that has it. For `in` and `notIn` that is a list of the field's
type; for `has`, a boolean.
