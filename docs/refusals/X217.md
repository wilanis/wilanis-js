# X217

- **Family:** X -- plugin rules, @storage (@wilanis/plugin-storage)
- **Status:** live, since 0.1.0
- **Made in:** `packages/plugin-storage/src/kept.ts`
- **Proved by:** `packages/runtime/test/sabotage-storage.test.ts` (`X217 keptBy naming this tree, which keeps its own stores`)

## Refuses when

A store's `keptBy` is this tree's own `project.json → name`. `keptBy` names another tree, the one that writes the
records and migrates them (RFC 0042). A tree that named itself would never migrate its own store: `wilanis migrate`
would skip it and exit 0, and the first sign would be a missing table at run time.

The name is compared with `project.json → name`, which is the name `wilanis migrate` and `ensure` write into the
record (`treeOf` in `packages/plugin-storage/src/record.ts`). So the rule and the record agree on what "this tree"
is. The refusal sits at `keptBy`.

## Example

The example's `project.json` says `"name": "customers"`. Add `"keptBy": "customers"` to
`@customers/data/customers.store.json`:

```
X217  @features/customers/data/customers.store.json#keptBy
    keptBy names customers, which is this tree's own project.json → name
    → keptBy names another tree; this tree keeps its own stores, so remove keptBy
```

The writes through the store are refused as X215 beside it, since the store now says another tree keeps it.

## Fix

Remove `keptBy`: this tree keeps the store. If another tree keeps the records, write that tree's `project.json →
name` instead.
