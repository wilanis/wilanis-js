# L007

- **Family:** L -- layers, effects and visibility
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/graph.ts`, `packages/compiler/src/check/bindings.ts`
- **Proved by:** `packages/runtime/test/sabotage.test.ts` (`L007 a domain graph that only forwards its input to one
  port operation`)

## Refuses when

A document sits in the domain or data layer without doing that layer's work. Two forms, both about the file as a
whole (no `at`):

- a domain graph whose one node is a `run` of a domain operation that passes each input as `{{in.<name>}}` under the
  same name and nothing else, with no `constants` and no `reads`: it adds no rule of its own, and the trigger could
  fire that operation directly;
- a binding outside every feature: a binding lives inside a feature folder, whose `effects` say what it may reach.

## Example

Strip the customers `register-customer` graph down to one node that forwards `id` to `customer.port.json#get`:

```
L007  @features/customers/domain/register-customer.graph.json
    graph only forwards its input to '@customers/domain/customer.port.json#get'
    → it adds no rule of its own; fire @customers/domain/customer.port.json#get from the trigger and delete this graph
```

The B005, T005 and T006 that follow in the example come from the graph's new contract, not from the forwarding. A
binding outside a feature reads `a binding lives inside a feature folder`, with the hint `move it under
features/<name>/`.

## Fix

For a forwarding graph: fire the operation it forwards to from the trigger, and delete the graph and the binding
operation that pointed at it. If the graph is meant to hold a rule, write the rule (a switch, a constant, a second
call), and the refusal goes. For a binding outside a feature: move it under `features/<name>/data/`, in the feature
whose `effects` allow what it delegates to.
