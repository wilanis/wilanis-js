# T009

- **Family:** T -- triggers
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/delivery.ts`
- **Proved by:** `packages/runtime/test/sabotage-delivery.test.ts` (`T009 an at-least-once connection firing an
  operation that does not promise idempotent`)

## Refuses when

A trigger whose kind declares `connection` receives from the connection its settings name there, and that
connection's kind declares `"delivery": "at-least-once"`, but the domain operation `fire.run` names does not declare
`"idempotent": true` (RFC 0011's word on an operation). A broker that delivers at least once hands a message again
when the process did not acknowledge it (a worker that died between the effect and the acknowledgement), so what
the trigger fires may run twice for one message, and only an operation that promises a second call changes nothing
further is safe to fire there. A `pure` operation is idempotent by definition and is not refused.

The rule reads the promise and nothing else. Whether the promise holds under each profile, over the effects the
operation's binding reaches, is B011's judgement, so the promise T009 asks for cannot be written falsely: a
`#submit` that POSTs cannot say it.

## Example

Drop `"idempotent": true` from `customer.port.json#remove`, which `remove-queued.trigger.json` fires from the
at-least-once memory broker of `jobs.connection.json`:

```
T009  @features/customers/edge/remove-queued.trigger.json#fire/run
    '@connections/jobs.connection.json' delivers a message at least once, so '@customers/domain/customer.port.json#remove' may run twice for one message, and the operation does not promise idempotent
    → declare "idempotent": true on @customers/domain/customer.port.json#remove (the checker then holds every profile to it, B011), or receive from a connection whose kind delivers at most once
```

## Fix

Declare `"idempotent": true` on the operation, in its domain port, where calling it twice with the same inputs
changes nothing further; `wilanis check` then holds every profile's binding to the promise (B011), and a profile
whose effects are not idempotent is refused there, naming the node. Where the operation cannot be made safe to
repeat, fire one that can (a removal rather than a creation, or a write keyed by the message), or receive from a
connection whose kind delivers at most once, accepting that a message may then not run at all.
