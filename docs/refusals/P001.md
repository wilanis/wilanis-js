# P001

- **Family:** P -- static fields and resolvers
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/inputs.ts`
- **Proved by:** `packages/runtime/test/sabotage.test.ts` (`P001 a static field given a read`, `P001 a reason given as a read: the checker must see the word`)

## Refuses when

A call site gives a read (`{{...}}`) where the operation needs a value the checker can see before anything runs.
Two kinds of input are held to it. A field the port marks `static` -- an http `method`, a refusal's `reason` -- is
judged at check time, so it must be written as a literal: `'<name>' is static: write the value, not a read`. A field
that is a type reference (the `type` that `@std/object.port.json#make` and `@std/outcome.port.json#refuse` take)
names a shape the checker reads for its layer and binds to the operation's type variable, so it must be a literal
string: `'<name>' is a type reference, written as a literal string`. Both sit at `nodes/<id>/in/<name>` in a graph,
or at the delegated input in a binding.

## Example

Give the get-row graph's refusal a reason read from the answer rather than the word:

```
P001  @features/customers/data/get-row.graph.json#nodes/noCustomer/in/reason
    'reason' is static: write the value, not a read
    → a static field is judged before anything runs
```

The type form, a `make` node given `"type": "{{in.id}}"`:

```
P001  @features/customers/data/kept-get.graph.json#nodes/customer/in/type
    'type' is a type reference, written as a literal string
    → e.g. "@features/tasks/domain/Task.shape.json[]"
```

## Fix

Write the value itself. A static field that must vary is a routing question, not a template: a switch chooses
between nodes that each carry their own literal (two `refuse` nodes with two reasons, two requests with two methods).
A type reference is the shape's path, with `[]` after it for a list. A refusal that follows from the unknown type,
such as G010 on the graph's `out`, goes with this fix.
