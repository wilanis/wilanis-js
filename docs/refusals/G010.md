# G010

- **Family:** G -- graphs
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/graph-whole.ts`
- **Proved by:** `packages/runtime/test/sabotage.test.ts` (`G010 a second out candidate that is never routed`)

## Refuses when

What a graph declares as its answer does not hold together. `out` has a type but `out.from` names no node; `out.from`
names a node the graph does not have, or a switch, which routes and answers nothing; a candidate answers a type not
assignable to `out.type`; or, where `out.from` lists several candidates, one of them no switch routes, so it always
settles and the candidates after it are dead. Candidates are alternatives, one per branch. Every form sits at
`out/from`.

## Example

List two candidates under `digest`'s `out.from`, neither behind a switch:

```
G010  @features/customers/domain/digest.graph.json#out/from
    out.from candidate 'joined' is never routed -- it always settles, so later candidates are dead
    → candidates are alternatives; each one sits behind a switch
```

The same sabotage names nodes that answer other types than `out.type`, so it also reads `'joined' answers string but
out is @features/customers/domain/Digest.shape.json: ...`, with the hint `make out.type and what 'joined' answers one
type`.

## Fix

Name the node whose answer the graph gives. With several candidates, put each behind the switch rule of its branch.
For a type that does not fit, make `out.type` and what the node answers one type, or name the node that answers it.
