# G010

- **Family:** G -- graphs
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/graph-whole.ts`
- **Proved by:** `packages/runtime/test/sabotage.test.ts` (`G010 a second out candidate that is never routed`, `G010 an open row answered where a closed Customer is declared, the run refusing what it carries beyond (#787)`)

## Refuses when

What a graph declares as its answer does not hold together. `out` has a type but `out.from` names no node; `out.from`
names a node the graph does not have, or a switch, which routes and answers nothing; a candidate answers a type not
assignable to `out.type`; or, where `out.from` lists several candidates, one of them no switch routes, so it always
settles and the candidates after it are dead. Candidates are alternatives, one per branch. Every form sits at
`out/from`.

## Example

List two candidates under `digest`'s `out.from`, neither behind a switch:

```
G010  @features/customers/domain/digest.graph.json#out/from
    out.from candidate 'joined' is never routed -- it always settles, so later candidates are dead
    → candidates are alternatives; each one sits behind a switch
```

The same sabotage names nodes that answer other types than `out.type`, so it also reads `'joined' answers string but
out is @features/customers/domain/Digest.shape.json: ...`, with the hint `make out.type and what 'joined' answers one
type`.

A closed `out.type` takes only a value of its own fields. Make `get-row`'s `customer` the row as the API answers it,
`@customers/edge/CustomerRow.shape.json`, which is open, and the run would refuse whatever the API adds beyond what a
Customer declares; check says so first:

```
G010  @features/customers/data/get-row.graph.json#out/from
    'customer' answers @features/customers/edge/CustomerRow.shape.json but out is @features/customers/domain/Customer.shape.json: @features/customers/edge/CustomerRow.shape.json is open and may carry fields @features/customers/domain/Customer.shape.json does not declare
    → make what 'customer' answers a @features/customers/domain/Customer.shape.json of the fields it declares: @std/object.port.json#make with "type": "@features/customers/domain/Customer.shape.json" narrows it
```

## Fix

Name the node whose answer the graph gives. With several candidates, put each behind the switch rule of its branch.
For a type that does not fit, make `out.type` and what the node answers one type, or name the node that answers it.
Where what is answered is open, or declares more than a closed `out.type`, narrow it: `@std/object.port.json#make`
handed the value whole, with `"type"` the closed shape, keeps only the fields it declares, and is the one place a
value is narrowed so.

- 0.1.0: a closed `out.type` refuses an open answer, or one declaring a field it does not; the hint says to narrow it (#787).
