# X203

- **Family:** X -- plugin rules, @storage (@wilanis/plugin-storage)
- **Status:** live, since 0.1.0
- **Made in:** `packages/plugin-storage/src/rules.ts`
- **Proved by:** `packages/plugin-storage/test/rules.test.ts` (`X203 a connection of a kind that reaches no storage engine`), (`X203 a connection of a kind no loaded plugin grants`)

## Refuses when

A store's `connection` is of a kind that does not reach a storage engine: its connection kind does not say
`"storage": true`, or no loaded plugin grants that kind at all. Only the kind document can say that a connection
reaches an engine, and an engine is what `@storage` hands a store's calls to. The refusal sits at `connection` of the
store.

## Example

Put the customers store on the customers API's HTTP connection:

```
X203  @features/customers/data/customers.store.json#connection
    '@connections/customers-api.connection.json' is of kind '@http/http.connection-kind.json', which does not say "storage": true, so it reaches no engine
    → add the engine's plugin to project.json → plugins; wilanis ls connection
```

A connection whose kind no loaded plugin grants reads `is of kind '<kind>', which no loaded plugin grants`.

## Fix

Point the store at a connection of a storage kind, which `wilanis ls connection` shows. If the connection is the
right one and its kind is an engine's (`@storage-memory`, `@storage-postgres`), the engine's plugin is missing from
`project.json → plugins`: add it.
