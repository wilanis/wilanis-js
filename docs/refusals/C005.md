# C005

- **Family:** C -- connections, settings and stores
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/stores.ts`
- **Proved by:** `packages/runtime/test/sabotage-storage.test.ts` (`C005 a reference to a collection this store does not declare`)

## Refuses when

A reference under `refs` names a collection that is not one of this store's, or names a view, which keeps no records
of its own to refer to. A reference stays within one store, since that is where the engine can hold it. It points at
`collections/<name>/refs/<field>` and lists the collections that keep records.

## Example

Refer the example's `email` to a collection that is not there:

```
C005  @features/customers/data/customers.store.json#collections/customers/refs/email
    'nowhere' is not a collection of this store (collections: customers, latest)
    → a reference stays within one store; declare the collection here, or read it by a second get
```

A reference to a view says `'<view>' views '<collection>' and keeps no records of its own`.

## Fix

Name a collection this store keeps, as the message lists them. If the records referred to live in another store,
there is no reference to declare: read them by a second `get`.
