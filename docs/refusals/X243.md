# X243

- **Family:** X -- plugin rules, @storage-mysql (@wilanis/plugin-storage-mysql)
- **Status:** live, since 0.1.0
- **Made in:** `packages/plugin-storage-mysql/src/rules.ts`
- **Proved by:** `packages/plugin-storage-mysql/test/rules.test.ts` (`X243 a collection name longer than MySQL keeps a table name`, `X243 two collections of one connection that fold to one table name`, `X243 a field name longer than MySQL keeps a column name`, `X243 two fields of one shape that fold to one column name`)

## Refuses when

A collection kept over a mysql connection has a name MySQL will not keep as a table, or a field MySQL will not keep
as a column. Four forms:

- the collection name is longer than 64 characters, the most MySQL keeps in a table name, at `collections/<name>`;
- the collection name folds to the same lower-case name as a collection seen before it on the same connection, at
  `collections/<name>`. Whether MySQL compares table names with case is the host's `lower_case_table_names`, so the
  engine assumes the strict case: `entriesKept` and `entrieskept` are one table somewhere. The later of the two is
  refused;
- a field of the kept shape has a name longer than 64 characters, the most MySQL keeps in a column name, at
  `collections/<name>/of`;
- two fields of the kept shape fold to the same lower-case name, at `collections/<name>/of`. MySQL compares column
  names without case on every host, so `userId` and `userid` are one column, and `CREATE TABLE` fails with a
  duplicate column. The later of the two is refused, naming both.

The store's schema covers table names only: it admits a collection name as a lower-case letter, then letters,
digits or underscores (D001), and MySQL creates every such name, so a table name is judged here by its length and
its fold. The shape's schema caps a field name at no length, so this rule judges the columns too. A `blob` field
has no column and is X241's. Two stores that declare one name with different shapes are @storage's to refuse
(X207); this rule refuses what only the fold makes one.

## Example

Declare `entriesKept` and `entrieskept` in the customers store, over a mysql connection:

```
X243  @features/customers/data/customers.store.json#collections/entrieskept
    'entrieskept' and 'entriesKept' are one table once folded to lower case, and a host with lower_case_table_names set compares names without case
    → rename one of the two collections
```

A collection name over 64 characters reads `'<name>' is 65 characters, and MySQL keeps a table name of 64 at most`,
with the hint `rename the collection to 64 characters or fewer`. A field name over 64 characters reads
`'<field>' is 65 characters, and MySQL keeps a column name of 64 at most`, with the hint `rename the field in the
shape to 64 characters or fewer`. Two fields `hits` and `hitS` in one shape read `'hitS' and 'hits' are one column
once folded to lower case, and MySQL compares column names without case`, with the hint `rename one of the two
fields in the shape`.

## Fix

Rename the collection, or one of the two that fold together, to a name of 64 characters or fewer that is distinct
once lower-cased; every graph and binding that names the collection must follow the rename. For a field, rename it
in the shape the same way; every graph that reads or writes the field must follow. A collection that already holds
rows keeps them only if it records its old name under `was`, so a migration renames the table rather than dropping
it.
