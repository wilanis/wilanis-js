# S002

- **Family:** S -- scenarios
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/scenarios.ts`
- **Proved by:** `packages/runtime/test/sabotage-scenario.test.ts` (`refuses a reason on a node that answered, at the reason`),
  `packages/runtime/test/sabotage-shared-answers.test.ts` (`refuses a shared answer with a reason that ended done, at
  nodes/<digest>/reason, and not in each scenario`)

## Refuses when

A scenario's `expect.nodes` pins a `reason` on a node whose expected `status` is not `failed`. A reason is the word
a node that refused gives (RFC 0014); a node that did not fail gave none, so a pinned reason there
expects something no run can produce. The refusal sits at `expect/nodes/<node>/reason`.

A recorded scenario may point at a shared answer instead of writing it (RFC 0036). That answer is judged once, in the
answers document that holds it, since its status and its reason are both in that one answer: the refusal sits at
`nodes/<digest>/reason` of `answers.json`, and no scenario that points at it is refused for it.

## Example

```
S002  @scenarios/pinned.scenario.json#expect/nodes/op.customer/reason
    node 'op.customer' pins reason 'missing' but ended 'done': only a node that refused gives a reason
    → a reason belongs to a node that refused; drop it, or let wilanis fuzz write the scenario again
```

In an answers document the message names the shared answer by its digest (`shared answer '57a449dbd5d11643' pins
reason ...`), and the hint says to record the directory again: `wilanis rehearse --record (or wilanis fuzz --edges)
writes the answers file again: run it and review the diff`.

## Fix

Drop the `reason`, or, if the node should have refused, set its `status` to `failed` beside it. A scenario written by
hand is the usual source; `wilanis fuzz` writes the scenario from a run and never pins a reason on a node that did
not refuse, so writing it again settles both fields. In an answers document, record the directory again with the
command that owns it; never edit `answers.json` by hand.

## History

- 0.1.0: introduced. Before the release, it came to judge the shared answers of an answers document (RFC 0036).
