# G004

- **Family:** G -- graphs
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/inputs.ts`, `packages/compiler/src/check/graph-nodes.ts`
- **Proved by:** `packages/runtime/test/sabotage.test.ts` (`G004 an optional read feeding a required input`)

## Refuses when

A value given to an input does not fit what the input takes. Either the read may be missing at run time and the
contract requires the field (`'<name>' may be missing at run time but <operation> requires it`), or its type is not
assignable to the field's (`'<name>': <why>`). A read is optional when it reaches an optional field or a node only
some branches run; a switch on `has(...)` that routes to the reader proves it present. A `map` whose `over` may be
missing is refused the same way, at `nodes/<id>/over`. The refusal sits at the input, `nodes/<id>/in/<field>` in a
graph and `operations/<name>/in/<field>` in a binding's delegation. Where the value joins two nodes' answers with `||`,
the hint says that branches meet at `out.from` instead.

## Example

Make the switch of `list-customers` route to `byTier` whatever the tier, so nothing proves `tier` present:

```
G004  @features/customers/domain/list-customers.graph.json#nodes/byTier/in/tier
    'tier' may be missing at run time but '@customers/domain/customer.port.json#listByTier' requires it
    → route around it with a switch on has(...), or make the contract field optional
```

## Fix

For a missing value, put the reader behind a switch whose rule tests `has(...)` of what it reads, or make the
contract's field optional if the operation can do without it. For a type that does not fit, make what is read and what
the input takes one type. Two answers joined with `||` become two nodes, one per branch, both listed under `out.from`.
Loosening a contract to quiet the refusal is wrong when the operation needs the value.
