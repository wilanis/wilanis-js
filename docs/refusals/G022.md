# G022

- **Family:** G -- graphs
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/graph-nodes.ts`
- **Proved by:** `packages/runtime/test/sabotage-catch.test.ts` (`refuses a reader beside the switch, which would wait on a node that broke`)

## Refuses when

A node other than the catching switch reads a node whose fault a switch catches, and does not run behind that switch.
When the caught node breaks, the switch routes the fault and the run carries on, but a reader beside the switch would
wait on a node that produced nothing. So every other reader of a caught node runs only where the switch routes. The
refusal sits at the reader's `nodes/<id>/in`.

## Example

With `get-row`'s catch in place, add a node `logged` beside the switch that reads `fetched`:

```
G022  @features/customers/data/get-row.graph.json#nodes/logged/in
    reads 'fetched', whose fault 'outcome' catches, but does not run behind 'outcome'
    → a reader of a node whose fault is caught runs only where the switch routes: move it behind the switch, or drop catch
```

## Fix

Move the reader behind the switch: make it, or a node that leads to it, the `to` of one of the switch's rules. If it
must run on every call, it cannot read a node that may break with no value; drop the `catch` and let the fault be a
fault.
