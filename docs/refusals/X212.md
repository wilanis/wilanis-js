# X212

- **Family:** X -- plugin rules, @storage (@wilanis/plugin-storage)
- **Status:** live, since 0.1.0
- **Made in:** `packages/plugin-storage/src/rules.ts`
- **Proved by:** `packages/runtime/test/sabotage-storage.test.ts` (`X212 ensure run by a graph node: it prepares the engine once, before the port opens`)

## Refuses when

`@storage/storage.port.json#ensure` prepares the engine for a store once, before the port opens, and two places are
refused for calling it. A data graph's node that runs it is refused at `nodes/<id>/in`, since a graph runs on every
request. A binding operation that delegates to it is refused at `operations/<name>/in` unless some startup step of
`project.json` names that domain operation under a profile that binds the port to this binding, since otherwise
nothing prepares what it prepares.

## Example

Remove the step that runs the customers port's `prepare` from `project.json → startup`, and both bindings that
delegate it to `ensure` are refused:

```
X212  @features/customers/data/customers-store.binding.json#operations/prepare/in
    this delegates to ensure, and no startup step reaches it under any profile
    → name the domain operation in project.json → startup; ensure runs once, before the port opens
```

A graph node that runs `ensure` reads `ensure prepares the engine once, before the port opens, and a graph never runs
it`, beside the G rules its other inputs break.

## Fix

Name the domain operation whose binding delegates to `ensure` in a startup step (`{ "run":
"@customers/domain/customer.port.json#prepare" }`). A graph that ran `ensure` should run the operation it meant, and
leave the preparing to that step.
