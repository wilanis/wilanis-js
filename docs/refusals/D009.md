# D009

- **Family:** D -- documents
- **Status:** live, since 0.1.0
- **Made in:** `packages/core/src/load.ts`
- **Proved by:** `packages/runtime/test/sabotage-access.test.ts` (`D009 a local feature the include also ships; D010 an include that is not a tree, or one asking a feature it does not ship or a plugin the project lacks`)

## Refuses when

A feature of an included tree has the name of a feature the host tree already has. The loader walks an include's
`features/` as if they were local, so two features of one name would have one of them silently shadow the other;
it refuses instead, at the include's entry (`includes/<index>`), and registers none of the included feature's
documents. What names them is refused as well, usually as R001.

## Example

Add a local `features/access/` beside the included access tree:

```
D009  project.json#includes/0
    feature 'access' is both in this tree and included from '@wilanis/access'
    → rename the local feature, or leave it out of the include with "features"
R001  @project.json#profiles/live/bindings
    profile 'live' names unknown port '@access/domain/identity.port.json'
    → wilanis ls port
```

## Fix

Rename the local feature, or list under the include's `features` only the ones the host does not have. When the
local feature was a copy of the included one, delete it and use the include.
