# L010

- **Family:** L -- layers, effects and visibility
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/atomic.ts`
- **Proved by:** `packages/runtime/test/sabotage-atomic.test.ts` (`is refused, since one transaction is one
  connection -- L010`), `packages/runtime/test/sabotage-served.test.ts` (`L010 once, under the profile that serves the
  routes running the atomic graph`)

## Refuses when

A graph marked `"atomic": true` reaches, under some profile that runs it, transactional effects on two or more
connections. One transaction is one connection, so a graph that writes two stores on two connections cannot commit
them together. The refusal is at the atomic graph's `atomic`, names the connections and the profiles that fall on
them, and is made by every atomic graph whose walk reaches the fault: a graph that runs another atomic graph below it
answers for it too. Which profiles run a graph is read as L009 reads it: those whose chosen binding lists it behind an
operation something the profile serves reaches, so a profile that never listens is not named for a graph only routes
reach.

## Example

Plant a second store on a connection of its own, and have the atomic `store-and-latest` data graph also write to it:

```
L010  @features/customers/data/store-and-latest.graph.json#atomic
    atomic graph reaches effects on 2 connections (@connections/customers.connection.json, @connections/notes.connection.json) (profile 'local')
    → one transaction is one connection; split the graph, or move both stores to one connection
L010  @features/customers/domain/register-all.graph.json#atomic
    atomic graph reaches effects on 2 connections (@connections/customers.connection.json, @connections/notes.connection.json) (profile 'local')
    → one transaction is one connection; split the graph, or move both stores to one connection
```

## Fix

Keep the stores the graph writes together on one connection, or split the graph so each transaction writes one
connection and decide what the caller does when the second fails. Where only one profile's binding puts the effects
on two connections, the fix may be that profile's binding or connection.
