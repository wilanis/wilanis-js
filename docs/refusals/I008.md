## Refuses when

A call runs `@storage/store.port.json#put` over a collection whose shape a field invariant holds over, and the record
it writes is not a value a site of that shape holds. The collection's shape is the `$T` the call's `store` resolves.
A site is where RFC 0007 judges a value of the shape: a graph whose `in` is the shape, or a node that makes one
(`sitesOf`). So:

- a `record` given to a graph's node must be one whole read of such a site in that graph -- `"{{in}}"` where `in` is
  the shape, or `"{{customer}}"` where `customer` makes one. An object written out at the write, a field of another
  value (`{{stored.record}}`, `{{in.customer}}`), a string with more than one read in it, or a whole read of an `in`
  or a node that is not a site of the shape (an `in` of a wider shape) is refused;
- a `record` a `map` binds from each element must be each element whole of one whole read of a site that holds a
  list of the shape -- `"over": "{{in}}"` where `in` is a list of it. A field of each element, or a list read from
  what is no site (`{{in.customers}}`), is refused;
- a binding's operation that delegates straight to `#put` is refused whatever it writes: a binding holds no site, so
  nothing judges what it hands the store.

The refusal sits at `nodes/<id>/in/record`, at `nodes/<id>/bind/record` for a map's bound element, or at
`operations/<op>/in/record` in a binding (at `operations/<op>/run` where the binding passes `record` on by name). The
message names the shape, where the record came from, and the invariant.

A record no site holds is a value nothing judged, so the compiler has nowhere to put the guard RFC 0007 lowers: it
would stand at the first node that reads the stored record, after the store has kept it. Read whole from a site, the
record is a value the graph took or made before the write, and judged there. `"record": "{{in}}"` over a graph whose
`in` is the shape is the form the example's `keep-customer` takes.

## Example

```
I008  @features/customers/data/keep-customer.graph.json#nodes/stored/in/record
    the Customer written here is composed at the write, so nothing judges it against 'A customer is reachable' (@features/customers/domain/a-customer-is-reachable.invariant.json) before the store keeps it
    → make the Customer whole before the write -- @std/object.port.json#make with "type": "@features/customers/domain/Customer.shape.json", in a domain graph that hands it to this one as in -- and give #put "record": "{{in}}"
```

A binding that delegates `#put` is told `the Customer written here is read from 'in', which is no site of it, ...`
and hinted `meet this operation with a data graph whose in is the Customer, and give its #put "record": "{{in}}",
where the compiler judges it`.

## Fix

Make the record where it can be judged and hand it to the write whole. A domain graph makes it with
`@std/object.port.json#make` (or `#merge`, laying a change over the record as kept) and passes it to an operation that
takes the whole shape; the data graph behind that operation takes it as its `in` and writes `"record": "{{in}}"`. The
guard at that `in` judges the value again before the write, whoever the caller is. A binding meets such an operation
with that data graph rather than delegating to `#put` itself.
