# L002

- **Family:** L -- layers, effects and visibility
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/graph.ts`, `packages/compiler/src/check/resolvers.ts`
- **Proved by:** `packages/runtime/test/sabotage.test.ts` (`L002 an effect run from a domain graph`),
  `packages/runtime/test/sabotage-reads.test.ts` (`L002 a domain graph that reads the request`)

## Refuses when

A graph runs, or reads, what its layer may not. The directory is the layer, and each layer has one job:

- a domain graph runs a native operation that is not `pure`: the domain says what is done, and reaches an effect
  only through a domain port whose binding runs it (at `nodes/<id>`);
- a data graph runs a domain operation: a data graph implements a domain port and speaks native ports only (at
  `nodes/<id>`);
- a domain graph declares `reads`: the request is read in the data layer, by the data graph or the binding that
  binds a resolver under its `reads` (at `reads`).

## Example

Make the first node of the customers `digest` domain graph send an HTTP request:

```
L002  @features/customers/domain/digest.graph.json#nodes/all
    domain graph runs effectful native operation '@http/http.port.json#request'
    → reach the effect through a domain port whose binding runs it
```

G-family refusals about the node's new answer follow, and go with the L002. Give the same graph a `reads` entry
instead, and it is refused at `reads`, saying `a domain graph never reads the request`, with the hint `read the
request in the data layer: the data graph or the binding binds it under reads`. A data graph running a domain
operation reads `data graph runs domain operation '<run>'` and hints `a data graph implements a domain port; it
speaks native ports only`.

## Fix

For an effect in a domain graph: declare an operation on a domain port for what the effect achieves, bind it in the
data layer to a data graph or a delegation that runs the native operation, and run the domain operation from the
graph. For a domain operation in a data graph: the graph is in the wrong layer, or it should run the native
operations that operation's own binding runs. For `reads` on a domain graph: move the read to the data graph or
binding that needs the value, and pass the domain what it needs as an input.
