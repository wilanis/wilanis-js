# C013

- **Family:** C -- connections, settings and stores
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/scopes.ts`
- **Proved by:** `packages/runtime/test/sabotage-scoping.test.ts` (`C013 a view of a collection this store does not declare`); `packages/runtime/test/sabotage-scoping.test.ts` (`C013 a view of a collection that declares no scope`)

## Refuses when

A view does not name one scoped collection of the same store. A view sees every row of a collection across its
scopes, so it names a collection of this store (`view`), that collection keeps records rather than being a view
itself, and it declares `scoped` columns, or there is nothing to see across. It points at
`collections/<name>/view`. That the policy the view is behind (`behind`) exists is R001's.

## Example

Point the example's `everyCustomer` view at a collection that is not there:

```
C013  @features/customers/data/customers.store.json#collections/everyCustomer/view
    'nope' is not a collection of this store (collections: customers, latest, everyCustomer)
    → a view sees every row of one scoped collection of this store
```

A view of `latest`, which scopes nothing, says `'latest' declares no scoped columns, so every row of it is seen
already` with the hint `scope the collection this views, or read it directly: a view is the way across a scope`.
A graph that reads the view is refused as well (G010), since the view no longer answers the shape it expects; that
refusal goes with the fix.

## Fix

Name a scoped collection of this store. If the collection viewed is not scoped, drop the view and read the
collection directly.
