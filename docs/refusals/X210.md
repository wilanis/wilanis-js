# X210

- **Family:** X -- plugin rules, @storage (@wilanis/plugin-storage)
- **Status:** live, since 0.1.0
- **Made in:** `packages/plugin-storage/src/filters.ts`
- **Proved by:** `packages/plugin-storage/test/rules.test.ts` (`X210 an operator the grammar does not name, or one the field type does not admit`)

## Refuses when

A call's `where` breaks the grammar `@storage/store.port.json` describes under *The where grammar*: it names an
operator the grammar does not have, or one the field's type does not admit, such as `contains` on a number or `gt` on
a boolean. The message lists the operators the field does admit. The `at` is the path of the operator inside `where`.

## Example

Filter `kept-list`'s find with an operator the grammar does not name:

```
X210  @features/customers/data/kept-list.graph.json#nodes/customers/in/where/email/like
    'like' is not an operator of 'email' (operators: eq, ne, lt, lte, gt, gte, in, notIn, has, contains, startsWith)
    → see The where grammar in @storage/store.port.json
```

## Fix

Use one of the operators the message lists; `wilanis describe @storage/store.port.json` prints the grammar. A pattern
match is `contains` or `startsWith` on a string field.
