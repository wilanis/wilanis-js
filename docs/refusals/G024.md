# G024

- **Family:** G -- graphs
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/graph-nodes.ts`
- **Proved by:** `packages/runtime/test/sabotage-catch.test.ts` (`refuses catching a pure operation`, `refuses catching a map that only keeps: it runs nothing that could break`)

## Refuses when

A switch's `catch` names a node that breaks only by a bug: another switch (`catches switch '<id>', which routes and has
no effect to break`), a map that only keeps (`catches '<id>', which only keeps the elements its where holds for: it
has no effect to break`), a node running a `pure` operation (`catches '<id>', which runs pure '<op>'`), or one running an
operation that is not pure but refuses on purpose (`catches '<id>', which runs '<op>': it refuses on purpose, never
caught`). Only an effect breaks for a reason outside the program, and a refusal is never caught at all.
`@std/outcome.port.json#refuse` is itself pure, so a catch of a `refuse` node is refused in the pure form. The refusal
sits at `nodes/<switch>/catch/<caught>`.

## Example

Put a pure `make` between `get-row`'s GET and its switch, and catch that:

```
G024  @features/customers/data/get-row.graph.json#nodes/outcome/catch/status
    catches 'status', which runs pure '@std/object.port.json#make'
    → nothing here breaks but a bug, which rehearse reports as BROKE; delete catch
```

## Fix

Delete the entry from `catch`. If the effect behind the caught node is what may break, have the switch read that
effect in its `in` and catch it instead.

## History

- 0.1.0: introduced.
- 0.1.0: a map with no `run` is caught as a switch is: it runs nothing that could break (RFC 0039).
