# X404

- **Family:** X -- plugin rules, @queue (@wilanis/plugin-queue)
- **Status:** live, since 0.1.0
- **Made in:** `packages/plugin-queue/src/publishes.ts`
- **Proved by:** `packages/plugin-queue/test/rules.test.ts` (`X404: a message carrying a blob`: `a queue trigger's message, naming where the blob sits`, `a publish's type`)

## Refuses when

A queue trigger's `settings.message`, or the `type` of a `publish`, names a type with a `blob` field at any depth --
in a nested object, a list's elements, or what an open object admits. A blob value is a handle to bytes held in one
process's blob registry, and a message is read by another process, or by this one after a restart, where the handle
names nothing. The refusal sits at `settings/message` of the trigger or `nodes/<id>/in/type` of the graph, and says
where in the type the blob is.

## Example

Consume a shape that carries a file:

```
X404  @features/customers/edge/removals.trigger.json#settings/message
    '@features/customers/edge/Upload.shape.json' carries a blob at rows.file, and a message leaves the process whose blob registry holds its bytes
    → bytes live in the blob registry and a handle is process-local; publish the handle's id as a string and read the bytes where the message is consumed
```

## Fix

Put somewhere both processes reach what the message would have carried -- a store, an object bucket -- and publish a
string that names it; the consuming trigger's graph reads the bytes from there. A message body is JSON of an edge
shape, buffered whole, and never a file.
