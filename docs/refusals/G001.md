# G001

- **Family:** G -- graphs
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/graph.ts`
- **Proved by:** `packages/runtime/test/sabotage-unproved.test.ts` (`G001 two nodes with one id`)

## Refuses when

A graph's node takes an id another node of the same graph already has (`duplicate node id '<id>'`), or an id that is
one of the roots a read may name, `in`, `const`, `request` or `secrets` (`node id '<id>' is reserved`). A read names a
node by its id, so an id must say one node, and one that is also a root would make `{{const.x}}` mean two things. The
refusal sits at `nodes/<id>`; the second of two nodes with one id is refused and not judged further.

## Example

Copy the first node of `list-rows` to the end of its `nodes`:

```
G001  @features/customers/data/list-rows.graph.json#nodes/fetched
    duplicate node id 'fetched'
    → give each node an id of its own
```

Rename a node `const` and it is refused as `node id 'const' is reserved`, with the hint `rename the node; in, const,
request, secrets are roots a read may name`.

## Fix

Rename one of the two nodes, for what it holds, and update every read of it (`{{<id>}}`, a switch's `to`, `out.from`).
A copied node that was meant to be the same node is removed instead. A reserved id is renamed the same way, and the
reads that meant the node, rather than the root, follow the new name.
