# C020

- **Family:** C -- connections, settings and stores
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/contracts.ts`
- **Proved by:** `packages/runtime/test/sabotage-listens.test.ts` (`C020 an endpoint the kind does not declare, or one
  that is not a string`, `C020 follows a dotted path into a nested setting`)

## Refuses when

A connection kind's `endpoint` names a path its `settings` do not declare, or one whose type is not a string.
`endpoint` says which setting holds the address a connection of the kind reaches (RFC 0024), as a dotted path
into `settings` (`baseUrl`, `broker.url`), and an address is written as a string. The kind is judged on its own,
whether or not a connection of the tree names it, so a plugin author meets the refusal and a tree author never
does. It points at `endpoint`, and the hint lists every string setting of the kind by its dotted path.

## Example

Give `@http/http.connection-kind.json` `"endpoint": "url"`, a setting it does not declare:

```
C020  @http/http.connection-kind.json#endpoint
    'endpoint' names 'url', which this kind's settings do not declare
    → name a string setting of this kind: baseUrl
```

`"endpoint": "headers"`, which the kind declares as an open object of strings, reads `which is {, ...}, not a
string` with the same hint.

## Fix

Name the string setting that holds the address, by its path from `settings`. A kind whose connections reach no
host, as a directory written in the document does, declares no `endpoint` at all.
