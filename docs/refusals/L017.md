# L017

- **Family:** L -- layers, effects and visibility
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/listen-settings.ts`
- **Proved by:** `packages/runtime/test/sabotage-listens.test.ts` (`L017 a port read from a setting @http does not
  declare, or one that is not a number`, `L017 an interface read from a setting that is not a string`, `L017 says to
  declare a setting where @http declares none of the type`, `L017 a setting on a port no plugin grants, which has no
  plugin settings to read`)

## Refuses when

An operation's `listens.port.setting` names no field of the granting plugin's settings, or one whose type is not
`number`; or its `listens.host.setting` names no such field, or one whose type is not `string`. The granting plugin
is the one the port is native to, and its settings are `settings.fields` in that plugin's `plugin.json`. Where the
startup step writes no `in` for a part, the part is read from that setting, which the project writes under the
plugin's `settings`; a setting the plugin does not declare is one no project can write, so the part would fall back
to `default` without a word, and `wilanis describe` would name a place the address never comes from. Each part is
its own refusal, at `operations/<name>/listens/port/setting` or `operations/<name>/listens/host/setting`. The hint
lists the plugin's settings of the right type.

A port no plugin grants, such as a tree's own, has no plugin settings to read, so any `setting` on it is refused.

## Example

Point `listens.port.setting` of `@http/server.port.json`'s `listen` at `prot`, a setting `@http` does not declare:

```
L017  @http/server.port.json#operations/listen/listens/port/setting
    operation 'listen' reads its port from @http settings.prot, which @http does not declare
    → name a number setting @http declares: port, deadlineMs, maxBodyBytes
```

Pointed at `host`, the message reads `which is string, not number`; `listens.host.setting` pointed at `port` reads
`which is number, not string` and the hint lists the string settings, `host`. Where the plugin declares no setting
of the part's type, the hint reads `none -- declare one in plugin.json, or drop "setting"`.

## Fix

Name a setting the plugin's `plugin.json` declares under `settings.fields`, of the part's type, or declare one: a
`number` setting for the port, a `string` setting for the interface. Drop `setting` when no setting is meant to fix
that part, and the step's input or the default then decides it; on a port no plugin grants, drop it.
