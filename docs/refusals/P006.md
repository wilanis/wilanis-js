# P006

- **Family:** P -- static fields and resolvers
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/resolvers.ts`, `packages/compiler/src/check/graph.ts`
- **Proved by:** `packages/runtime/test/sabotage-reads.test.ts` (`P006 says the same thing wherever the read was bound, and points at the entry`, `P006 a read named like a node of the graph`)

## Refuses when

A local name under `reads` would make `{{name}}` ambiguous. Wherever the read is bound -- a data graph, a binding or
a store -- the name may not be a root, `in`, `const`, `request` or `secrets` (`read name '<name>' is reserved`). In a
data graph it may also not be the id of one of the graph's nodes (`'<name>' is also the id of a node; {{<name>}}
would be ambiguous`), since otherwise the order roots are tried in would decide silently which one a template means.
The refusal sits at `reads/<name>`. The same rule for a resolver's own name in its resolvers document is P003.

## Example

```
P006  @features/customers/data/create-row.graph.json#reads/in
    read name 'in' is reserved
    → in, const, request, secrets are roots; pick another name
```

The node form, a read bound as `customer` in a graph that has a node `customer`:

```
P006  @features/customers/data/create-row.graph.json#reads/customer
    'customer' is also the id of a node; {{customer}} would be ambiguous
    → rename the read: "reads": { "customerBy": "...#customer" }
```

## Fix

Rename the local name, and every `{{name}}` that meant the read; the resolver the entry names stays as it is. A
cycle (G007) reported beside the node form, because a node's inputs now read a name that is also a node, goes with
the rename.
