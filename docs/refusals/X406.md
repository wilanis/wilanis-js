# X406

- **Family:** X -- plugin rules, @queue (@wilanis/plugin-queue)
- **Status:** live, since 0.1.0
- **Made in:** `packages/plugin-queue/src/rules.ts`
- **Proved by:** `packages/plugin-queue/test/rules.test.ts` (`X406: two queue triggers receiving from one queue`, from `a second trigger on the same connection and queue: refused on the second, naming the first` to `the same queue name on another connection, or another queue on the same one, is another queue`)

## Refuses when

Two queue triggers of one tree receive from the same connection and queue. A delivery fires one trigger: the worker
consumes each connection and queue once, and hands each message to the first trigger the tree lists that receives
from it, so every later one is written and never runs. The place is compared the way the worker compares it, the
connection by its canonical path and the queue by its name, so the same queue name on two connections is two
queues. Each trigger after the first is refused on its own file, in the order the tree lists them, at
`settings/queue`, and the message names the trigger that already receives from it.

## Example

Copy the removals trigger to a second file, on the same connection and queue:

```
X406  @features/customers/edge/sweep.trigger.json#settings/queue
    receives from queue 'removals' of '@connections/jobs.connection.json', as @features/customers/edge/removals.trigger.json already does: a message on it fires @features/customers/edge/removals.trigger.json, so this trigger never runs
    → one trigger per queue: remove @features/customers/edge/sweep.trigger.json, or change its settings.queue to a queue no other trigger receives from
```

## Fix

Where the two triggers do the same work, remove the one the refusal names. Where they do different work, give the
refused trigger a queue of its own in `settings.queue` and publish that work there; a message that should do both
things is one trigger firing one operation that does both, since a queue here is a point-to-point channel and not a
topic every subscriber hears.
