## Refuses when

A call runs `@storage/store.port.json#patch` over a collection whose shape a field invariant holds over, and the
`changes` it writes name a field that invariant's `holds.when` reads, or are of a type open to one. The collection's
shape is the `$T` the call's `store` resolves, the type `#put` writes as `record`. The call is a graph's `run` or
`map` node, or a binding's operation that delegates straight to `#patch`. The fields `changes` names are read off
what the call writes:

- its keys, where it is written out as an object;
- the fields of its type, where it is one whole read of `in`, of a constant or of a node, typed as the graph types
  that read (a node that merges a `CustomerUpdate` writes every field `CustomerUpdate` has);
- the fields of what a `map` binds as `changes` from each element of the list it runs over;
- in a binding, the fields of what it reads of the operation's `in`, typed off what the operation accepts.

Where that type is `unknown`, or an object whose `open` is not `false`, a value of it may carry a field it does not
declare, so `changes` writes every field the invariants on the collection's shape read, whatever fields it declares
besides: a constant typed `{ "fields": {}, "open": "string" }`, a field of `in` of that type, and the body of an
`@http/http.port.json#request` with no `returns`, read after a switch on `has(body)`, are each refused. A closed object
writes only the fields it declares. Where the type cannot be told at all, because the read does not resolve, `changes`
names no field and is not refused here: the read is refused where the graph is judged. The refusal sits at
`nodes/<id>/in/changes`, at `nodes/<id>/bind/changes` for a map's bound element, or at `operations/<op>/in/changes` in
a binding (at `operations/<op>/run` where the binding passes `changes` on by name). The message names each field
written and the invariant that reads it, and where the type is open or `unknown` says so, since that is why every
field the invariant reads is named.

A patch sets some fields and leaves the rest, so it can make a rule over several fields false without the graph ever
holding the record that breaks it. There is no value above the write for the compiler to guard (RFC 0007), and the
guard at the first node that reads the patched record judges it only after the store has kept it. A patch of a field
no invariant reads (`active` on `Customer`) is not refused, and neither is a patch of a collection no invariant holds
over.

## Example

```
I007  @features/customers/data/keep-customer.graph.json#nodes/stored/in/changes
    patch writes 'tier', which 'A customer is reachable' (@features/customers/domain/a-customer-is-reachable.invariant.json) reads; a rule over the whole record cannot be held on a part of one
    → load the record, make the new one with @std/object.port.json#merge in a domain graph, and #put it whole through an operation that takes a Customer
```

## Fix

Write the record whole, made where it can be judged before the write (RFC 0035). A domain graph loads the record
(`#get` through the domain port), lays the change over it with `@std/object.port.json#merge`, and hands the result to
an operation that takes the whole shape; the data graph behind that operation writes it with `#put` and
`"record": "{{in}}"`. The example's `update-customer` and `keep-customer` are that pair. If the field should not be
held to the rule, change the invariant's `holds.when`, which the whole tree is then held to.

## History

- 0.1.0: introduced (RFC 0035).
- 0.1.0: judges a `changes` read of a node, a map's bound element and a binding's delegation (#682).
- 0.1.0: a `changes` of type `unknown`, or of an object type whose `open` is not `false`, writes every field the
  invariants on the shape read, where before it named only the fields its type declares, so a patch that could carry
  `tier` passed (#489).
