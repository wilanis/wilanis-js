# G030

- **Family:** G -- graphs
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/graph-after.ts`
- **Proved by:** `packages/runtime/test/sabotage-after.test.ts` (`refuses a node read in in, and says the read`)

## Refuses when

A run or a map names a node under `after` that it already reads, in its `in` or, for a map, in its `over` (RFC 0041).
A node waits for whatever it reads, so the entry adds nothing, and the document would say a wait twice. The message
names the read that makes the wait. Only a direct read is refused: a node that waits for `x` and reads a node that
reads `x` is not, since that wait is still true and finding it would take a walk over the whole graph. The refusal
sits at the entry, `nodes/<id>/after/<index>`.

## Example

In `kept-get`, have `customer` wait for `stored`, which it reads already:

```
G030  @features/customers/data/kept-get.graph.json#nodes/customer/after/0
    'customer' already waits for 'stored': it reads {{stored.record}}
    → drop 'stored' from after; a node waits for whatever it reads
```

## Fix

Drop the entry from `after`. If `after` is then empty, drop `after` too: the schema asks for at least one entry.
