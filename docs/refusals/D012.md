# D012

- **Family:** D -- documents
- **Status:** live, since 0.1.0
- **Made in:** `packages/core/src/documents.ts`
- **Proved by:** `packages/runtime/test/required-port.test.ts` (`D012 when the manifest both grants and requires one path`, `D012 when the manifest requires a port it does not ship`)

## Refuses when

A plugin's `plugin.json` lists under `requires.ports` a port it cannot require. A required port is one the plugin
calls and the host binds (RFC 0005): it ships under the plugin's `docs/` and is registered as an open domain port,
not a native one. So a path under `requires.ports` may not also be under `grants.ports`, since a port is either the
plugin's to implement or the host's to bind; and it must be a port document under that plugin's own `docs/`. `at` is
`requires/ports/<index>` of the plugin's manifest. Like D011, this is a broken plugin, not a broken tree.

## Example

A plugin `@keep` that grants and requires the same port:

```
D012  @keep/plugin.json#requires/ports/0
    '@keep/memory.port.json' is both granted and required: a port is the plugin's to implement or the host's to bind, never both
    → list it once: under grants.ports if the plugin implements it, under requires.ports if the host binds it
```

And one requiring a port it does not ship:

```
D012  @keep/plugin.json#requires/ports/1
    '@keep/absent.port.json' is required, but no port by that path is under @keep's docs/
    → add the port document under the plugin's docs/, or remove '@keep/absent.port.json' from requires.ports
```

## Fix

List the port once in the manifest: under `grants.ports` when the plugin's handlers implement it, under
`requires.ports` when the host binds it. For a required port, ship its document under the plugin's `docs/`; a port of
another plugin cannot be required through this one.
