# G026

- **Family:** G -- graphs
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/inputs.ts`, `packages/compiler/src/check/project.ts`
- **Proved by:** `packages/runtime/test/site.test.ts` (`G026 a node writing the site the compiler provides`, `G026 a
  binding operation writing it`, `G026 a startup step writing it`)

## Refuses when

A call site gives a value for a field the operation's contract marks `provided` (RFC 0032). The compiler writes that
field where the operation is called -- the calling document and the position within it, as `@std/Site.shape.json`
-- and an author never does: a value written there would either repeat what the compiler knows or lie about it.
The refusal sits at the offending key: `nodes/<id>/in/<field>` in a graph, `operations/<name>/in/<field>` in a
binding's delegation, `startup/<index>/in/<field>` in `project.json`. Leaving the field out is not refused: G005
passes a provided field over, since the site is not the author's to give.

## Example

Write `site` at a node calling an operation that asks for it:

```
G026  @features/customers/data/create-row.graph.json#nodes/noted/in/site
    'site' is provided by the compiler where '@note/note.port.json#record' is called
    → drop it; the operation is told where it was called without being asked
```

## Fix

Remove the key. The handler finds the site under its inputs all the same, and the report shows it under the node's
`in` beside what the author gave.
