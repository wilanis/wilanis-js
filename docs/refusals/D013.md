# D013

- **Family:** D -- documents
- **Status:** live, since 0.1.0
- **Made in:** `packages/core/src/ir-version.ts`
- **Proved by:** `packages/runtime/test/sabotage-ir-version.test.ts` (`D013 a document rewritten to a schemas-v2 URL,
  at its $schema, and no rule but the version rules runs`, `D013 says the version this runtime reads, the one the
  document names, and the edit that fixes it`), `packages/core/test/ir-version.test.ts` (`D013 a plugin whose docs/
  are of a version this runtime does not read, and the tree mixes versions`, `D013 at every document of a tree wholly
  of a version this runtime does not read, and no D014`)

## Refuses when

A document the loader reads names, in its `$schema`, an IR version this runtime does not read (RFC 0008). The version
is the ref the schema's address is read at: `main` and the tag `schemas-v1` serve v1, the tag `schemas-vN` serves vN.
The alias `@wilanis/<kind>.schema.json` names no version of its own and is read as the one this runtime reads. A
runtime reads one version, the one its own schema base serves, and `wilanis check` prints it as `IR v1, runtime reads
v1`.

The rule holds every document a load reads: the tree's, each include's `project.json` and the features taken from it,
and the `docs/` of each plugin the project names, so a plugin built for another version is refused at each document it
ships. It is judged from `$schema` alone, before any document is judged against a schema and before any other rule
runs. A tree it refuses is read no further: the loader answers it with D013 and D014 and nothing else, rather than
with a D001 for every difference between two versions' schemas and an R001 for everything that names the document.
`at` is `$schema`.

## Example

Rewrite the customers port's `$schema` from `main` to the tag `schemas-v2`:

```
D013  features/customers/domain/customer.port.json#$schema
    names IR v2, which this runtime does not read
    → this runtime reads v1; the document names v2: upgrade @wilanis/runtime, or rewrite the document against v1, its $schema under https://raw.githubusercontent.com/wilanis/wilanis-js/main/packages/core/schemas
D014  project.json
    the documents of this tree name more than one IR version: v1 (221, connections/customers-api.connection.json among them), v2 (1, features/customers/domain/customer.port.json)
    → a tree is one version: upgrade the rest to the newer one, or rewrite every $schema against v1, under https://raw.githubusercontent.com/wilanis/wilanis-js/main/packages/core/schemas (docs/rfcs/0008-ir-versioning.md)
```

The one document of another version leaves the tree of two, so D014 stands beside it.

## Fix

Either the runtime catches up with the document or the document goes back to the runtime. Upgrade `@wilanis/runtime`
to a release that reads the document's version, with every other document of the tree moved to it too, since a tree
is one version (D014); or rewrite the document against the version this runtime reads, its `$schema` under the base
the hint names. `wilanis upgrade`, which will move a tree from one version to the next, is RFC 0008's step 4 and waits
for a second version to exist.

## History

- 0.1.0: introduced (RFC 0008). A `$schema` at the tag of another version was D001 before, as any address the
  loader did not know.
