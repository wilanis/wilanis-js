# P005

- **Family:** P -- static fields and resolvers
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/graph.ts`, `packages/compiler/src/check/bindings.ts`, `packages/compiler/src/check/scopes.ts`
- **Proved by:** `packages/runtime/test/sabotage-reads.test.ts` (`P005 a read the graph binds and no value of it reads`, `P005 a read a binding binds and no delegation of it reads`), `packages/runtime/test/sabotage-scoping.test.ts` (`P005 a reads entry no scoped collection of the store reads`)

## Refuses when

A document binds a read under `reads` and nothing in it reads that name. `reads` is exactly what the document reads,
as an import list is, and an entry nothing uses is refused as an unused import would be. A data graph's entry must
be read by some node's value (`'<name>' is used by no value of this graph`), a binding's by some delegation
(`'<name>' is used by no value of this binding`), and a store's by some collection's `scoped` column (`'<name>' is
read by no scoped collection of this store`). The refusal sits at `reads/<name>`. An entry already refused as P004
is not judged again.

## Example

A graph that binds `tenant` beside `agent` and reads only `{{agent}}`:

```
P005  @features/customers/data/create-row.graph.json#reads/tenant
    'tenant' is used by no value of this graph
    → read it as {{tenant}}, or drop the entry: reads is exactly what this document reads
```

## Fix

Drop the entry if nothing needs it. If something should read it, write `{{<name>}}` where the value goes, or, on a
store, scope a collection by it (`"scoped": { "<column>": "{{<name>}}" }`), as the store's hint says.
