# T002

- **Family:** T -- triggers
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/triggers.ts`
- **Proved by:** `packages/runtime/test/sabotage.test.ts` (`T002 a trigger whose edge shape does not fit the graph`)

## Refuses when

A trigger's edge shapes do not meet the contract of the domain operation it fires. Its `in` must be assignable to the
operation's `accepts`, field for field, and the operation's `returns` to the trigger's `out`. Each half is refused too
when only one side declares anything: the operation takes an input and the trigger declares no `in`, it answers and
the trigger declares no `out`, or the trigger declares an `out` for an operation that returns nothing. The refusal
sits at `in` or `out`, whichever side does not fit.

## Example

Delete `email` from the registration request's shape, and the trigger that fires `#submit` no longer carries what the
operation requires (the same edit earns a T003 as well, since `fire.in` still reads the field):

```
T002  @features/customers/edge/register-customer.trigger.json#in
    in → @customers/domain/customer.port.json#submit: missing required field 'email'
    → the edge shape must be assignable to the operation's core contract, field for field
```

## Fix

Make the edge shape carry what the operation takes, and the trigger's `out` what it answers; `wilanis describe` on the
operation shows its contract. Declare `in` or `out` where the message says one is missing, and remove an `out` the
operation cannot fill, or give the operation `returns`. The edge shape is usually the one to change: the domain
contract is what every trigger and binding of the port agrees on.
