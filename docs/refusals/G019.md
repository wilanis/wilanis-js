# G019

- **Family:** G -- graphs
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/attempts.ts`
- **Proved by:** `packages/runtime/test/sabotage-attempts.test.ts` (`G019 a retry whose when is not boolean over the answer, or whose answer is not an object`)

## Refuses when

A `retry.when` is not a boolean expression over the fields of what one try answers. `when` reads the answer's fields
as its inputs, and it is refused three ways: the answer is not an object, so there are no fields to read (`retry.when
reads the answer, which is blob, not an object`); the expression does not parse or does not type over those fields
(`retry.when: <what the parser or the type check said>`); or it types to something other than a boolean (`retry.when
'status' is number, not boolean`). The refusal sits at `nodes/<id>/retry/when` or `operations/<name>/retry/when`.

## Example

Retry `get-row`'s GET `when` its `status`, a number:

```
G019  @features/customers/data/get-row.graph.json#nodes/fetched/retry/when
    retry.when 'status' is number, not boolean
    → when reads the fields of the answer, e.g. status >= 500; a retry over an answer that is not an object needs no when
```

## Fix

Write `when` as a comparison over the answer's fields, `status >= 500`. Over an answer that is not an object, delete
`when`.
