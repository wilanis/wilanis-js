# L014

- **Family:** L -- layers, effects and visibility
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/contracts.ts`
- **Proved by:** `packages/runtime/test/sabotage-listens.test.ts` (`L014 listens without holds`)

## Refuses when

A port's operation declares `listens` but not `holds: true`. `listens` says the operation opens a TCP socket and
where each part of the address it binds comes from (RFC 0024); only something that keeps running after its run
has answered can listen, and that is what `holds` says. A plugin author meets this refusal on the port document
the plugin ships; a tree author never does. It points at the operation.

## Example

Remove `holds` from `@http/server.port.json`'s `listen`, which declares `listens`:

```
L014  @http/server.port.json#operations/listen
    operation 'listen' declares 'listens' but not 'holds' -- only something that keeps running can listen
    → add "holds": true, or drop "listens"
```

The example's `Listen` startup step then names a native operation that holds nothing, which B006 refuses beside it.

## Fix

Add `"holds": true` to the operation when it does keep a socket open until the process stops. Drop `listens` when
it does not: an operation that answers and ends binds nothing a deployment reaches.
