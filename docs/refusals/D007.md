# D007

- **Family:** D -- documents
- **Status:** live, since 0.1.0
- **Made in:** `packages/core/src/load.ts`
- **Proved by:** `packages/runtime/test/sabotage-unproved.test.ts` (`D007 an alias that collides with a folder of the tree`, `D007 an alias that collides with a plugin root`)

## Refuses when

An alias under `project.json → aliases` would make a path mean two things. An alias is a root such as `@customers`
that stands for a path of the tree, and it may not share its name with a plugin's root (`@http`), a reserved root
(`@wilanis`, `@features`, `@connections`, `@scenarios`), or a top-level folder of the tree (`@features` for
`features/`). An include brings its own aliases along, and one it declares with a different target than the host's
is refused too, at `includes/<index>`. The other forms sit at `aliases/<alias>`; one alias can break more than one
of these at once and earns a refusal for each.

## Example

Declare an alias named like a plugin's root:

```
D007  project.json#aliases/@http
    alias '@http' collides with plugin root '@http'
    → rename the alias under project.json → aliases
```

Give the host an `@access` of its own, which the included access tree already declares:

```
D007  project.json#includes/0
    alias '@access' is '@features/hello' here and '@features/access' in '@wilanis/access'
    → an include brings its aliases along; drop yours or rename it
```

## Fix

Rename the alias, and the references that use it, to a root nothing else claims. For the include form, drop the
host's alias: the include's already means what its documents need.
