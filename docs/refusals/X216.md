# X216

- **Family:** X -- plugin rules, @storage (@wilanis/plugin-storage)
- **Status:** live, since 0.1.0
- **Made in:** `packages/plugin-storage/src/kept.ts`
- **Proved by:** `packages/runtime/test/sabotage-storage.test.ts` (`X215 the ensure a startup step reaches, and X216 the store beside it on the connection that says none`)

## Refuses when

Two stores reach one connection and do not say the same `keptBy`: one says it and the other does not, or they name
two trees. `wilanis migrate` plans per connection, so one tree migrates a connection: either this tree keeps every
collection on it, or one other tree does (RFC 0042).

A store's connection is judged as it is reached under the unnamed profile and under every profile `project.json`
declares, since a profile may stand one connection in for another. That is the connection `wilanis migrate` groups
the stores by.

Each store that disagrees with another is refused once, under the first profile that brings the two together. A
store that says `keptBy` is refused at `keptBy`; a store that says none is refused at `connection`.

## Example

Say that the billing tree keeps `@customers/data/customers-postgres.store.json` (`"keptBy": "billing"`).
`@features/state/data/auth.store.json` sits on the same connection and says none, so both are refused:

```
X216  @features/customers/data/customers-postgres.store.json#keptBy
    this store says keptBy billing, and @features/state/data/auth.store.json over the same connection @connections/customers-postgres.connection.json says no keptBy
    → one tree migrates a connection: give every store over @connections/customers-postgres.connection.json the same keptBy, or move this store to a connection of its own
X216  @features/state/data/auth.store.json#connection
    this store says no keptBy, and @features/customers/data/customers-postgres.store.json over the same connection @connections/customers-postgres.connection.json says keptBy billing
    → one tree migrates a connection: give every store over @connections/customers-postgres.connection.json the same keptBy, or move this store to a connection of its own
```

Where only a profile brings the two stores together, the message says which, `... over the same connection
<path> under profile <name> ...`.

## Fix

Decide which tree migrates the connection. If another tree keeps every collection on it, give every store over it
the same `keptBy`. If this tree keeps some of them, move the kept store to a connection document of its own, which
may reach the same database.
