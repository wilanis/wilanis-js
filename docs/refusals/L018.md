# L018

- **Family:** L -- layers, effects and visibility
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/listen-settings.ts`
- **Proved by:** `packages/runtime/test/sabotage-listen-port.test.ts` (`L018 a step input of 70000, -1 or 1.5, where
  the step writes it`, `L018 an @http settings.port of 70000, -1 or 1.5, where the project writes it`, `L018 each
  place on its own, where both are written wrong`)

## Refuses when

A port the tree writes where an operation's `listens` reads it is not a whole number from 0 to 65535. The tree
writes a port in two places (RFC 0024): under `in` of a startup step that runs the operation, at the input
`listens.port.input` names, and under the `settings` of the plugin granting the port in `project.json`, at the
setting `listens.port.setting` names. A number there that is above 65535, below 0 or not whole is one no socket can
bind: the tree checks, and `wilanis start` then fails on `listen` with a `RangeError`. Each place is its own
refusal, made in `project.json` at `startup/<index>/in/<input>` or `plugins/<index>/settings/<setting>`, whether or
not the other place is written too.

Only a number written in the document is judged. A port read from a secret (`{{secrets.<key>}}`) is not known until
the tree starts, so L018 leaves it alone; a secret reads as a string, and where the place takes a number the type
rules judge it instead (B007 on a step's input, C002 in a plugin's settings). A place L015 or L017 already refuses,
an input the operation does not accept or a setting the plugin does not declare as a number, is not read. The
`default` a plugin writes in its own `listens` is the plugin's, not the tree's, and is not judged here.

## Example

Write `"port": 70000` under `@http`'s `settings` in the example's `project.json`:

```
L018  @project.json#plugins/2/settings/port
    @http settings.port is 70000, a port no socket can bind: 'listen' listens on a whole number from 0 to 65535
    → write a whole number from 0 to 65535 there (0 asks the system for any free port)
```

Written as the `Listen` step's `"in": { "port": 70000 }`, the refusal is at `startup/<index>/in/port` and the
message reads `startup step <index>'s in.port is 70000`. `-1` and `1.5` are refused the same way.

## Fix

Write a whole number from 0 to 65535 in the place the refusal points at. `0` asks the system for any free port,
which suits a test and not a deployment, since nothing outside the process can know the port in advance. Drop the
value instead, and the operation's address is taken from its next place: the plugin's setting after the step's
input, the `default` after the setting.
