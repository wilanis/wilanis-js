# C007

- **Family:** C -- connections, settings and stores
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/stores.ts`
- **Proved by:** `packages/runtime/test/sabotage-storage.test.ts` (`C007 a constraint that names the key, which identifies a record and is unique already`)

## Refuses when

A constraint names the collection's key: a `unique` entry that includes it, or a `refs` entry on it. The key is
unique already, and it identifies the record rather than referring to another. It points at
`collections/<name>/unique/<i>` or `collections/<name>/refs/<key>`. A `unique` that names one field twice is refused
by the schema (D001), not here.

## Example

Add the key to the example store's `unique`:

```
C007  @features/customers/data/customers.store.json#collections/customers/unique/1
    'id' keys this collection, so it is unique already
    → a key is unique already; a constraint names each field once
```

A reference on the key says `'id' keys this collection, so it identifies rather than refers`.

## Fix

Drop the key from the `unique` entry, or drop the entry if the key was all it named. For a reference on the key,
move it to the field that holds the other record's key.
