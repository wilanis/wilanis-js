# X102

- **Family:** X -- plugin rules, @auth (@wilanis/plugin-auth)
- **Status:** live, since 0.1.0
- **Made in:** `packages/plugin-auth/src/rules.ts`
- **Proved by:** `libraries/access/test/access.test.ts` (`X102 a challenge by a method the settings do not declare; X103 a session write outside the session shape`), `packages/plugin-auth/test/auth.test.ts` (`X102 a challenge no attachment of the trigger could answer`)

## Refuses when

A challenge could never be met, in one of two ways. A policy's outcome with `"effect": "challenge"` names a `method`
that the `@auth` plugin's `settings.challenge.methods` does not declare, so the guard would not know how a caller
obtains a code; that is refused on the policy at `outcomes/<reason>/method`. Or a trigger attaches a policy that may
challenge, and none of its attachments gives the guard a challenge answer (`in.challenge`), so a challenged caller
could never answer it; that is refused on the trigger at `policies`.

## Example

Challenge by a method the settings do not declare:

```
X102  @features/access/edge/otp-verified.policy.json#outcomes/otp/method
    outcome 'otp' challenges by method 'sms', which @auth settings.challenge.methods does not declare
    → declare it under project.json → plugins → @auth → settings.challenge.methods, with how a caller obtains a code
```

Attach the one-time-code policy bare, as `"policies": ["@access/edge/otp-verified.policy.json"]`, and the trigger is
refused:

```
X102  @features/hello/edge/hello-gated.trigger.json#policies
    a policy of this trigger may challenge the caller, but no attachment gives the guard a challenge answer, so the challenge could never be met
    → give it: "in": { "challenge": { "id": "{{request.flags['challenge-id']}}", "code": "{{request.flags.code}}" } }
```

That bare attachment also earns an A005, since the policy reads `request.challenge` and nothing hands it.

## Fix

For a method, declare it under `settings.challenge.methods` with how a caller obtains a code, or name one already
declared. For a trigger, write the attachment as an object and give the guard where the answer is read, as the hint
spells it, reading the id and the code from wherever the trigger's kind hands them.
