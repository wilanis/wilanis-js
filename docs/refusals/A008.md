# A008

- **Family:** A -- access
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/scope-access.ts`
- **Proved by:** `packages/runtime/test/sabotage-scope-access.test.ts` (`A008 a trigger reaching a view that attaches no such policy`)

## Refuses when

A trigger reaches a node that reads a store's view, and does not attach the policy the view is `behind`. A view is the
one way across a scope, a collection that sees every scope's rows, so the policy it names is a gate every trigger
reaching it carries. It is judged per profile, since which binding meets the fired operation decides which graph, and
so which collection, is reached; one refusal is made per crossing, naming each profile it was found under. It sits
at the `policies` of every trigger that reaches the view, not only of the one that seems to own it.

## Example

Drop the digest's policies, and under each profile whose binding reads the view it crosses every tenant ungated:

```
A008  @features/customers/edge/digest.trigger.json#policies
    reaches @features/customers/data/kept-list-every.graph.json#customers, which reads everyCustomer, a view of customers across every scope behind @access/edge/employees-only.policy.json, and attaches no such policy (profile 'local')
    → attach "@access/edge/employees-only.policy.json" under policies, or read customers
```

## Fix

Attach the policy the view names under the trigger's `policies`, giving the guard its credential if no earlier
attachment does, or have the graph read the scoped collection the hint names, so the trigger sees only its caller's
rows.
