# I006

- **Family:** I -- invariants
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/graph-nodes.ts`
- **Proved by:** `packages/runtime/test/sabotage-invariants.test.ts` (`I006 a refuse node an author wrote whose reason is the word a guard is refused with`)

## Refuses when

A node that runs an operation which refuses on purpose names its `reason` `invariant`. That word is the compiler's:
it is what a guard lowered at an unproved site refuses with (RFC 0007), so a trigger that maps it is told that a
value the tree made or took broke a rule someone declared. A graph writing the same word about something else would
leave the trigger unable to tell the two apart. The refusal sits at `nodes/<id>/in/reason`. It lives beside the other
node rules rather than with the invariants, since it judges the node.

## Example

```
I006  @features/customers/data/store-and-latest.graph.json#nodes/repeated/in/reason
    reason 'invariant' is reserved
    → choose another word; 'invariant' is what a guard the compiler lowers refuses with
```

## Fix

Give the refusal a word that says what went wrong at that node (`duplicate`, `missing`, `conflict`), and map that
word on the triggers that reach it. If the node was written to enforce a rule over a shape's fields, state the rule
as a field invariant instead and let the compiler guard it.
