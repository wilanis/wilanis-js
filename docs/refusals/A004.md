# A004

- **Family:** A -- access
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/access.ts`
- **Proved by:** `packages/runtime/test/sabotage-access.test.ts` (`A004 a credential the guard does not verify, one read where the kind hands nothing, and one no policy of the trigger reads`)

## Refuses when

A credential a trigger gives the guard, in a policy attachment's `in`, is wrong for this trigger. Four forms, the
first three at `policies/<index>/in/<name>`: the name is not a credential the guard verifies, or the project has no
guard at all; the credential is read from a path the trigger's kind does not hand (each place of a list of places is
judged on its own); or what is read does not fit the type the guard takes. The fourth is at `policies`: a credential
is given and verified, but no policy of the trigger reads anything it yields, so it is verified for nothing.

## Example

Give the registration route's first attachment a `badge` rather than a `token`:

```
A004  @features/customers/edge/register-customer.trigger.json#policies/0/in/badge
    'badge' is not a credential the guard verifies (it verifies token, challenge)
    → wilanis describe @auth/plugin.json
```

Give it a `challenge` beside its token, though neither policy reads `request.challenge`:

```
A004  @features/customers/edge/register-customer.trigger.json#policies
    credential 'challenge' is given, but no policy of this trigger reads what it yields (request.challenge)
    → drop it, or attach a policy that decides on it
```

Read the token from `{{request.flags.token}}` on an http route, and the message is `credential 'token': no field
'flags' in {...}`, the route's context, with the hint `wilanis describe @http/http.trigger-kind.json shows what this
kind hands`.

## Fix

Give only the credentials `wilanis describe` on the guard's `plugin.json` lists, read from where the kind hands them
(for http, `{{request.headers.authorization}}` for a token). Drop a credential no policy decides on, or attach the
policy that does. Without a guard, add a guarding plugin such as `@wilanis/plugin-auth` to `project.json → plugins`.
