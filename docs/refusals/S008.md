# S008

- **Family:** S -- scenarios
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/scenarios.ts`
- **Proved by:** `packages/runtime/test/sabotage-scenarios.test.ts` (`refuses a path that is no key of expect.nodes,
  at its place under broken`)

## Refuses when

A path under a scenario's `broken` is not a key of its `expect.nodes`. `wilanis regress` makes each broken node throw
where it runs, so the run reports it, failed. A path the run does not report is a node the replay never reaches: it
breaks nothing, and the catch branch the scenario was written for is not taken. The refusal sits at `broken/<index>`,
one per path.

The rule reads the scenario alone, as S003 judges `cancelAt` against the scenario's `stubs`. Whether the run still
reaches that node in the tree as it stands is `wilanis regress`'s to say.

## Example

```
S008  @scenarios/caught.scenario.json#broken/0
    broken names 'op.fetchd', which is not a node this scenario's run reports under expect.nodes
    → broken names a node of the run, one of the keys under expect.nodes, such as op.<node>: wilanis rehearse --record writes it for a catch branch
```

## Fix

Name the node the run breaks by its dotted path, as `expect.nodes` writes it (`op.fetched`, or `op.current.op.fetched`
for a node of a graph a call reached). A recorded scenario is written again with `wilanis rehearse --record`, which
writes `broken` for a switch's catch branch (`<node> broke`).
