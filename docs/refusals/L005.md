# L005

- **Family:** L -- layers, effects and visibility
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/judge.ts`
- **Proved by:** `packages/runtime/test/sabotage-unproved.test.ts` (`L005 a shape of another feature that feature
  does not export`), `packages/runtime/test/sabotage-project.test.ts` (`L005 a collection over another feature's
  shape that feature does not export`)

## Refuses when

A document of one feature names a document of another feature that it may not see. A native document, or one outside
every feature, is visible everywhere, and a feature sees its own. Beyond that, the naming feature must list the other
under `feature.json → dependsOn`, and the other must list the named document under `exports`. The message says which
of the two is missing: `feature '<ours>' does not declare dependsOn '<theirs>'`, or `feature '<theirs>' does not
export '<path>'`. A document outside every feature that names a feature's document is `(root)`, and never sees it.

`Judge.visible` is asked wherever a reference crosses documents: a type, an operation a graph, trigger, policy or
binding runs, a binding's port and graphs, a policy a trigger, store or invariant names, a store's connection and
shapes, and a resolver read. `at` is the place of that reference.

## Example

Type the hello feature's `Greeting` field as a shape of the customers feature, which hello does not depend on:

```
L005  @features/hello/domain/Greeting.shape.json#fields/greeting
    feature 'hello' does not declare dependsOn 'customers'
    → wilanis describe @features/customers/domain/Digest.shape.json shows who may name it
```

The G004 and T002 that follow come from the field's new type, which the graph and the trigger no longer fit. Where
hello does depend on customers but names `CustomerRecord`, which customers keeps to itself, the message reads
`feature 'customers' does not export '@features/customers/domain/CustomerRecord.shape.json'`.

## Fix

If the feature is meant to use the other's document, add the other feature to `dependsOn`, and have it export the
document if it does not; `wilanis describe <path>` shows who may name it today. If the document is the other
feature's own business, as a record shape behind a store usually is, name what that feature exports instead (its
core shape, its port) and leave the private one private.
