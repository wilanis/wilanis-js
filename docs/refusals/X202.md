# X202

- **Family:** X -- plugin rules, @storage (@wilanis/plugin-storage)
- **Status:** live, since 0.1.0
- **Made in:** `packages/plugin-storage/src/rules.ts`
- **Proved by:** `packages/plugin-storage/test/rules.test.ts` (`X202 a key the shape does not have, with the fields it does`), (`X202 a key that may be absent, since a key identifies every record`)

## Refuses when

A collection's `key` is not a field of the shape it keeps, or is a field the shape marks `"required": false`. The key
identifies every record of the collection, so every record must have it. The message lists the shape's fields when
the name is not one of them. The refusal sits at `collections/<name>/key` of the store.

## Example

Give the `latest` collection a key its shape does not have:

```
X202  @features/customers/data/customers.store.json#collections/latest/key
    'nope' is not a field of @customers/domain/TierLatest.shape.json (fields: tier, email, customer)
    → name a required field of the shape
```

Key the `customers` collection by the optional `note` instead, and it reads `'note' is optional in
@customers/domain/Customer.shape.json, and a key identifies every record`.

## Fix

Set `key` to a required field of the shape, one the message lists. If the field that identifies a record is optional
in the shape, make it required there, since a record without it could not be kept.
