# X001

- **Family:** X -- plugin rules, @http (@wilanis/plugin-http)
- **Status:** live, since 0.1.0
- **Made in:** `packages/plugin-http/src/rules.ts`
- **Proved by:** `packages/runtime/test/sabotage-unproved.test.ts` (`X001 a codec table that names something that is not a codec`)

## Refuses when

An entry of the `@http` plugin's `settings.codecs` in `project.json` names a path that is not a codec. The table maps
a content type to the codec that reads and writes bodies of that type, and an entry whose codec does not exist would
leave every body of that type with nothing to decode it. The refusal is about `@project.json` at
`plugins/@http/settings/codecs`, and the message names the content type and the path it gave.

## Example

Point `application/json` at a codec the plugin does not ship:

```
X001  @project.json#plugins/@http/settings/codecs
    codecs["application/json"] names '@http/codecs/nope.codec.json', which is not a codec
    → wilanis ls codec
```

## Fix

Run `wilanis ls codec` and write the path of one it lists, usually one under `@http/codecs/`. A content type no
codec handles yet needs a codec a plugin ships; the table cannot name one into existence.
