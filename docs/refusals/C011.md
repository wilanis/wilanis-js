# C011

- **Family:** C -- connections, settings and stores
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/stores.ts`
- **Proved by:** `packages/runtime/test/sabotage-storage.test.ts` (`C011 a was equal to the collection's own name, which was never renamed`); `packages/runtime/test/sabotage-storage.test.ts` (`C011 a was naming another collection of the same store`)

## Refuses when

A collection's `was` names something that is not a former name: the collection's own name, or a name another
collection on the same connection holds now, whether in this store or another one. The pair of connection and name
is a table, so a previous name still taken would rename one table onto another. It points at
`collections/<name>/was`.

## Example

Say the example's `latest` collection was once `customers`:

```
C011  @features/customers/data/customers.store.json#collections/latest/was
    'customers' names a collection of @features/customers/data/customers.store.json on this connection already
    → was is the collection's previous name on this connection, and no collection is named that now
```

A `was` equal to the collection's own name says `'<name>' is what this collection is called now, so it was never
renamed`.

## Fix

Write the name the collection's table really had before, or drop `was` if the collection was not renamed.
