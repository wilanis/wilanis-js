# I003

- **Family:** I -- invariants
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/invariants.ts`, `packages/compiler/src/check/invariant-holds.ts`
- **Proved by:** `packages/runtime/test/sabotage-invariants.test.ts` (`I003 an invariant over an operation no trigger reaches`, `I003 a rule over a core shape no graph makes or takes`)

## Refuses when

An invariant constrains nothing, as G008 says of an unread node. An access invariant is refused when no trigger
reaches, under any profile, any operation of its `over` (`no trigger reaches any operation of over, so this
invariant gates nothing`, at `access/over`). A field invariant is refused when no graph makes or takes a value of the
shape it `holds` over (`no graph makes or takes a value of this shape, so this invariant holds nothing`, at
`holds/on`). An invariant shipped by an included tree is exempt: a library says what it requires of whoever reaches
its ports, and is not wrong for carrying a rule this host does not exercise.

## Example

```
I003  @features/customers/domain/writes-are-for-registrars.invariant.json#access/over
    no trigger reaches any operation of over, so this invariant gates nothing
    → remove it, or name what a trigger reaches
```

## Fix

Name what the rule is about: the operation a trigger does reach (`wilanis describe` on the trigger lists what it
fires), or the shape a graph makes. If nothing reaches it because the way in is gone, the invariant has nothing left
to hold and is removed.
