# D008

- **Family:** D -- documents
- **Status:** live, since 0.1.0
- **Made in:** `packages/core/src/placement.ts`
- **Proved by:** `packages/runtime/test/sabotage.test.ts` (`D008 a port outside the domain layer`, `D008 a connection outside connections/`, `D008 a shape whose declared layer contradicts the directory it sits in`);
  `packages/runtime/test/sabotage-fixes.test.ts` (`D008 ${what} offers the one move to where its kind lives` and
  `D008 applying the move for ${what} leaves nothing refused`, each for `a connection under a feature`, `a port in
  the edge layer`, `a trigger in no layer`, `a scenario under a feature` and `a shape in the data layer`; `D008 a
  shape whose layer disagrees with its directory offers the layer set, and no move`, `D008 offers nothing for a kind
  with two layers, or outside any feature`)

## Refuses when

A document is not where its kind lives. The directory is the layer: `edge/` speaks the world, `domain/` holds the
business rules, `data/` translates and carries the effects, and the checker reads a document's role off its path.
`HOME` in `placement.ts` says where each kind is at home: a trigger, policy or resolvers document in `edge/`; a port
or invariant in `domain/`; a binding or store in `data/`; a graph in `domain/` or `data/`; a shape in `edge/` or
`domain/`; a connection under the tree's `connections/`, a scenario under `scenarios/`. The forms:

- a kind with a top-level directory outside it;
- a kind that lives in a feature, outside any feature;
- a document inside a feature but in no layer directory, or in a layer its kind may not live in;
- a shape whose `layer` disagrees with the directory it sits in (`at` is `layer`): `"layer": "edge"` belongs in
  `edge/`, anything else in `domain/`.

The hint says why the kind lives where it does and where to move it. For a kind with two layers it names the first
of them (`domain/` for a graph, `edge/` for a shape), which is a guess: the right one is the author's to say.

## Example

Move the customers port into the edge layer:

```
D008  features/customers/edge/customer.port.json
    a port may not live in the edge layer
    → a domain port is the contract the business offers; move it to features/customers/domain/customer.port.json
```

Give a domain shape an edge `layer`:

```
D008  features/customers/domain/Customer.shape.json#layer
    shape declares layer 'edge' but sits in domain/
    → a shape's layer is where it lives; move it to features/customers/edge/, or set "layer": "core"
```

## Fix

Move the file where the hint says when its kind has one home. For a graph or a shape, decide which layer it belongs
to first: a data graph moved to `domain/` only trades D008 for L002. For the shape form, either move the file or set
`layer`, whichever was meant. A misplaced document is not registered, so the R001s naming it go with the move.

Where the destination is a fact of `HOME`, the refusal offers the move as its one fix, to the path the hint spells:

```json
{ "file": "features/customers/data/customers-api.connection.json", "move": "connections/customers-api.connection.json" }
```

`file` is tree-relative, as D008 spells it, since the loader has not named the document. The move is offered for a
kind with a top-level directory (a connection to `connections/`, a scenario to `scenarios/`), for a kind with one
layer found in another or in none (a port to `domain/`, a trigger to `edge/`, ...), and for a shape in `data/`, moved
to the layer its `layer` declares. A shape in `edge/` or `domain/` whose `layer` disagrees offers `set` of `layer` to
the directory's (`"core"` under `domain/`, `"edge"` under `edge/`), and no move:

```json
{ "file": "features/customers/domain/Customer.shape.json", "at": "layer", "set": "core" }
```

The move is left out there because every reference to the shape names the directory it sits in, and moving it
leaves each of those behind as R001. The set is right where the field was what changed; where the file was moved and
the field kept, the set clears D008 and the references to the old path remain R001, whose hint says what to do.

Nothing is offered for a graph, or for a shape in no layer directory: a kind with two layers is the author's to place,
and a data graph moved to `domain/` would only trade D008 for L002. Nothing is offered for a layered kind outside any
feature either, since which feature it belongs to is not the rule's to say. `wilanis check` prints only the hint; the
suite applies every fix offered to the sabotaged example and holds that nothing is refused after.

## History

- 0.1.0: introduced. Before the release, it came to offer the move to where the kind lives, or the set of a shape's
  `layer`, as a fix (RFC 0019).
