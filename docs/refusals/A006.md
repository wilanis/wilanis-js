# A006

- **Family:** A -- access
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/triggers.ts`
- **Proved by:** `libraries/access/test/access.test.ts` (`A006 a resolver read as required that no policy of the trigger proves`),
  `packages/runtime/test/sabotage-served.test.ts` (`A006 once, under the profile that listens, where two profiles that
  both listen find it twice`)

## Refuses when

Something a trigger reaches reads a resolver declared `required`, the trigger's kind hands that path only sometimes,
and no policy the trigger attaches lists it, or a path above it, under `proves`. A required resolver is read as
present by construction, so each trigger that reaches it must guarantee it: the kind hands it always, or a policy
that allows only when it is there says so. The reads are gathered as T004 gathers them, through what the trigger
fires and what its policies decide, profile by profile, and a store's `scoped` read reaches every site over its
collection. The refusal sits at the trigger's `policies` and names the document that reads.

It is judged only under a profile that serves the trigger: one with a startup step naming the `holds` operation the
plugin granting the trigger's kind grants beside it (`@http/server.port.json#listen` for a route,
`@queue/worker.port.json#consume` for a queue trigger). A profile that never opens the route reads nothing on its
behalf. A kind whose plugin grants no such operation, as `@cli`'s, is served under every profile, and so is a trigger
no profile serves, so a tree that listens nowhere is still judged.

## Example

Delete `proves` from `signed-in`, and every trigger it gates reaches a graph that reads the session id as required:

```
A006  @features/access/edge/get-preferences.trigger.json#policies
    @features/access/data/read-session.graph.json reads request.session.id as required, but trigger kind '@http/http.trigger-kind.json' hands it only sometimes and no policy of this trigger proves it
    → gate this trigger with a policy whose proves lists "request.session.id", or drop required from the resolver and route around its absence
```

In the example, drop the get route's policies, and the tenant each store scopes by is owed under each profile that
listens and keeps a store, with `(profile 'local')` and `(profile 'production')` at the end of the message.
`production-scheduler` and `production-worker` bind production's store too, but neither listens, so neither is named.

## Fix

Attach a policy whose `proves` lists the path, as the hint spells it, or restore the `proves` that was there. If the
value may truly be absent, drop `required` from the resolver and let the graph route around its absence; a graph that
feeds it to a required input is then refused where it reads it (G004).
