# G005

- **Family:** G -- graphs
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/inputs.ts`
- **Proved by:** `packages/runtime/test/sabotage.test.ts` (`G005 a required input left unwired`)

## Refuses when

A call site gives no value for an input its operation requires: a field of `accepts` not marked `required: false`,
or a type field the operation needs, is absent from the node's `in` (`<operation> requires input '<name>'`, or
`requires '<name>'` for a type field). The refusal sits at `nodes/<id>/in` in a graph and at the delegation's `in` in a
binding. A `refuse` node without its `reason` is the same rule: `@std/outcome.port.json#refuse` requires one.

## Example

Delete `email` from what `register-customer` gives `register`:

```
G005  @features/customers/domain/register-customer.graph.json#nodes/registered/in
    '@customers/domain/customer.port.json#register' requires input 'email'
    → give it under in, or mark the field optional in '@customers/domain/customer.port.json#register'
```

A G008 on `in` comes with it, since `in.email` is now read by nothing.

## Fix

Give the input under the node's `in`, reading what the operation needs. Mark the field optional in the port only when
the operation can run without it, never to quiet the refusal. A `refuse` node is given its reason as a literal word.
