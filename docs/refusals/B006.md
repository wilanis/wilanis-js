# B006

- **Family:** B -- bindings, profiles and startup
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/project.ts`
- **Proved by:** `packages/runtime/test/sabotage-project.test.ts` (`B006 a startup step naming an operation the port does not have`, `B006 a startup step firing a native operation`)

## Refuses when

A step of `project.json → startup` fires a domain port operation once, before anything is received, so that the
profile's binding decides how it is met. The step's `run` is refused at `startup/<index>/run` when it names no
operation, because the port or the operation does not exist or because it names something that is not an operation,
such as a trigger kind; and when it names a native operation, unless that operation is marked `holds` (a listener, a
watcher). A `holds` operation is the one native operation a step may name, since it has no per-profile binding.

## Example

Name an operation the customer port does not have:

```
B006  @project.json#startup/0/run
    startup step 0: port '@customers/domain/customer.port.json' has no operation 'nope' (operations: listAll, listEvery, listByTier, get, register, update, remove, removeMany, submit, registerAll, list, digest, parseDrafts, toCsv, import, export, prepare, repair, backfill, listRaw)
    → wilanis ls port
```

Name `@http/http.port.json#request` instead:

```
B006  @project.json#startup/0/run
    startup step 0 fires native operation '@http/http.port.json#request'
    → a startup step fires a domain port; the port's binding reaches the native operation
```

In the example both bring X212 with them, since the step replaced was the one that reached `@storage`'s `ensure`.

## Fix

For a name that resolves to nothing, correct it to an operation the message lists (`wilanis ls port`). For a native
operation, declare a domain operation for what the step should do and bind it, under each profile, to a delegation or
a data graph that runs the native one; the step then names the domain operation.
