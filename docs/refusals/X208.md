# X208

- **Family:** X -- plugin rules, @storage (@wilanis/plugin-storage)
- **Status:** live, since 0.1.0
- **Made in:** `packages/plugin-storage/src/filters.ts`
- **Proved by:** `packages/plugin-storage/test/rules.test.ts` (`X208 a filter naming a field the shape does not have, at any nesting`), (`X208 an order by a field the shape does not have`); `packages/runtime/test/sabotage-scoping.test.ts` (`X208 a where naming the scope column: a scope is the store's column, never a field to filter on`)

## Refuses when

A call's `where` tests a field the collection's shape does not have, at any depth under `all`, `any` and `not`, or an
entry of its `order` sorts `by` a field the shape does not have. A filter is judged against the shape the collection
declares, with the same parse an engine compiles, so a misspelled field is caught before any engine sees it. A scoped
collection's scope column is not a field of the shape, so a `where` naming it is refused here too. The `at` is the
path of the field inside `where` (`.../in/where/any/0/<field>`), or `.../in/order/<index>/by`.

## Example

Filter `kept-list`'s find by a misspelled field:

```
X208  @features/customers/data/kept-list.graph.json#nodes/customers/in/where/emial
    'emial' is not a field of the collection's shape (fields: id, name, email, tier, registrar, active, note)
    → wilanis describe @customers/data/customers.store.json
```

An `order` by a field the shape lacks is refused at `nodes/customers/in/order/0/by` with the same message.

## Fix

Name a field the message lists. If the filter was meant to narrow by who is calling, that is the store's `scoped`
column, which the compiler applies to every call; drop the test from `where`.
