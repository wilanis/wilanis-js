# T003

- **Family:** T -- triggers
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/triggers.ts`
- **Proved by:** `packages/runtime/test/sabotage.test.ts` (`T003 a route placeholder the route does not declare`)

## Refuses when

A trigger's `fire.in` does not read the request into the trigger's `in`. There are three forms, all at `fire/in`:
`fire.in` is given but the trigger declares no `in`; it reads something other than `request.*`, or a path of the
request the kind does not hand under these settings (a route's `params` are exactly the placeholders its `route`
declares); or what it reads does not fit the trigger's `in`. The fit is wire-loose: a read that may be missing, such
as a query key or a header, may feed a required field, since the edge judges the input when it arrives and refuses a
request without it before anything runs.

## Example

Rename the get route's placeholder to `{customer}` while `fire.in` still reads `request.params.id`:

```
T003  @features/customers/edge/get-customer.trigger.json#fire/in
    fire.in: id: no field 'id' in {customer: string}
    → wilanis describe @http/http.trigger-kind.json shows what this kind hands
```

## Fix

Read what the kind hands: `wilanis describe` on the kind lists its context, and for a route the `params` are the
placeholders of `settings.route`. Where the read resolves but its type does not fit, make `fire.in` and the trigger's
`in` one shape. Where the trigger has no `in`, declare one or remove `fire.in`.
