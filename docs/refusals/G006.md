# G006

- **Family:** G -- graphs
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/inputs.ts`, `packages/compiler/src/check/graph-nodes.ts`
- **Proved by:** `packages/runtime/test/sabotage.test.ts` (`G006 an input the operation does not declare`)

## Refuses when

A call site gives a value the operation does not take: a key under `in` that is no input of the operation (`'<name>'
is not an input of <operation> (inputs: ...)`, the message listing those it has). A `map` adds two forms: giving
`item` under `in`, which is the element the map hands each run, and giving a name under `in` that `bind` already
binds from the element. A map that says `where` and `bind` also refuses `item` under `in`, since the rule reads the
element as `item` (`'item' is the element in where; do not give it in in`). The refusal sits at the offending key, `nodes/<id>/in/<name>` or `nodes/<id>/bind/<name>`, and
at `operations/<name>/in/<key>` in a binding's delegation.

## Example

Give the http request of `list-rows` a `query` it does not take:

```
G006  @features/customers/data/list-rows.graph.json#nodes/fetched/in/query
    'query' is not an input of '@http/http.port.json#request' (inputs: connection, method, path, headers, body, consumes, produces, returns)
    → wilanis describe <port>
```

## Fix

Remove the key, or rename it to the input it meant; `wilanis describe` on the port lists what the operation takes. In
a `map`, drop `item` from `in`, and drop a bound name from `in` or bind it under another name. Beside a `where`, rename
the input; in a where, `item` is the element.

## History

- 0.1.0: introduced.
- 0.1.0: a map that says `where` and `bind` gives no input named `item` (RFC 0039).
