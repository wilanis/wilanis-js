# L008

- **Family:** L -- layers, effects and visibility
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/graph.ts`
- **Proved by:** `packages/runtime/test/startup.test.ts` (`L008 a graph may not run what outlives the run`),
  `packages/runtime/test/sabotage-schedule.test.ts` (`L008 a data graph running the scheduler`)

## Refuses when

A graph's node runs an operation its port marks `holds`: one that starts something outliving the run, such as the
HTTP listener (`@http/server.port.json#listen`), the scheduler (`@schedule/scheduler.port.json#run`), the reload
watcher or the OpenTelemetry exporter. What a tree starts is declared in one place, `project.json → startup`, and only
a startup step may name such an operation; a graph that did would start it again on every run. `at` is the node.

## Example

Make the first node of the customers `get-row` data graph run the HTTP listener:

```
L008  @features/customers/data/get-row.graph.json#nodes/fetched
    node 'fetched' runs '@http/server.port.json#listen', which starts something that outlives the run
    → name it in project.json → startup, where what a tree starts is declared
```

The other refusals the example earns here (L003 for the effect, G003 and G011 for the answer the rest of the graph
read) come from the same edit.

## Fix

Take the node out of the graph and add a step `{ "run": "<port>#<operation>" }` to `project.json → startup`, in the
order the tree needs it. If the graph wanted something the running thing produces, read it through an operation that
answers within the run rather than starting it.
