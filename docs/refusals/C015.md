# C015

- **Family:** C -- connections, settings and stores
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/contracts.ts`
- **Proved by:** `packages/runtime/test/sabotage-attempts.test.ts` (`C015 a native operation whose key is not a field, that says idempotent and key, or whose idempotent is not boolean`); `packages/runtime/test/sabotage-attempts.test.ts` (`C015 a domain operation that names a key, or promises idempotent only under an expression`)

## Refuses when

What a port operation says about repeating it is not one sound fact. On a native operation: a `key` names a field
the operation does not accept; `key` and `idempotent` are both written, where one says it; a `pure` operation says
either, being idempotent already; or `idempotent` is an expression that does not type as boolean over the accepted
fields. On a domain operation: any `key`, since the field a key names belongs to the native operation its binding
reaches, and an `idempotent` that is an expression, since only `true` is a promise its bindings can be held to
(B011). It points at `operations/<name>/key`, `operations/<name>/idempotent`, or the operation.

## Example

Give the customer port's `get` a key:

```
C015  @features/customers/domain/customer.port.json#operations/get/key
    domain operation 'get' declares key 'id'
    → a domain operation may say "idempotent": true; the field a key names belongs to the native operation its binding reaches
```

On a native port, `@http`'s `request` made idempotent when `method`:

```
C015  @http/http.port.json#operations/request/idempotent
    operation 'request' is idempotent when 'method', which is "GET" | "POST" | "PUT" | "PATCH" | "DELETE" | "HEAD" | "OPTIONS", not boolean
    → key names one accepted field; idempotent is true, or an expression over the accepted fields that is boolean; a pure operation is idempotent already
```

## Fix

On a domain operation, say `"idempotent": true` or nothing. On a native one, keep one of `key` (naming an accepted
field) and `idempotent` (true, or a boolean expression over the accepted fields, such as `method == 'GET'`), and
neither on a `pure` operation.
