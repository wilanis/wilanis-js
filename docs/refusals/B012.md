# B012

- **Family:** B -- bindings, profiles and startup
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/project.ts`
- **Proved by:** `packages/runtime/test/sabotage-profiles.test.ts` (`B012 a startup step naming a profile the project does not declare`)

## Refuses when

A step of `project.json → startup` lists the profiles it runs under in `profiles`, and one of them is not declared
under `project.json → profiles`. A step that names profiles runs only under those, so a misspelt or removed name
would quietly keep the step from running where it was meant to. The refusal points at the name,
`startup/<index>/profiles/<position>`, and the hint lists the profiles the project declares, or says it declares none.

## Example

Have the last startup step run under `staging`, which the example does not declare:

```
B012  @project.json#startup/9/profiles/0
    startup step 9 runs under profile 'staging', which project.json does not declare
    → name a declared profile: live, local, production, production-scheduler
```

## Fix

Correct the name to a profile the hint lists, or declare the profile under `profiles` if the step should run in a
place the tree does not describe yet. Where the project declares no profiles, remove `profiles` from the step, which
then runs on every start.
