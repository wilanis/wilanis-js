# G020

- **Family:** G -- graphs
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/atomic.ts`
- **Proved by:** `packages/runtime/test/sabotage-attempts.test.ts` (`refuses a node of the atomic graph itself, and says so for each atomic graph that reaches it`)

## Refuses when

Something below an atomic graph says `retry`: a node of the atomic graph itself, a node of a graph it reaches, or a
binding operation reached inside its transaction. A failed statement has aborted the transaction, so it cannot be
tried again inside it, and a binding operation reached inside would try again on a scope that joined the outer
transaction. A node of the atomic graph is refused whoever runs the graph, and its message names no profile; anything
further down is refused only under a profile that runs the atomic graph, and the message names those profiles. One
place is refused once for each atomic graph that reaches it. The refusal sits at `nodes/<id>/retry` or
`operations/<name>/retry`.

## Example

Retry the `stored` write of `store-and-latest`, which is atomic and which the atomic `register-all` reaches under
`local`:

```
G020  @features/customers/data/store-and-latest.graph.json#nodes/stored/retry
    node 'stored' retries inside the transaction of atomic graph '@features/customers/data/store-and-latest.graph.json'
    → a statement inside a transaction is not tried again; retry the binding operation that runs the atomic graph, so the transaction is
G020  @features/customers/data/store-and-latest.graph.json#nodes/stored/retry
    node 'stored' retries inside the transaction of atomic graph '@features/customers/domain/register-all.graph.json' (profile 'local')
    → a statement inside a transaction is not tried again; retry the binding operation that runs the atomic graph, so the transaction is
```

The same retry earns G018 as well, since `#put` declares neither `idempotent` nor `key`.

## Fix

Move the `retry` to the binding operation that runs the atomic graph (`registerAll` in the example's store binding).
Each of its tries is a transaction of its own and a failed one has rolled back, so the next starts from nothing.
