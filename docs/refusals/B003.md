# B003

- **Family:** B -- bindings, profiles and startup
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/bindings.ts`, `packages/compiler/src/check/project.ts`
- **Proved by:** `packages/runtime/test/sabotage-unproved.test.ts` (`B003 a binding that names a native port the plugin binds`)

## Refuses when

A native port is the plugin's: the plugin that grants it implements every operation, so nothing in the tree binds it.
Two places can try. A binding whose `port` is a native port is refused at `port` (`'<port>' is a native port; the
plugin binds it`), and the rest of that binding is not judged. A profile that lists a native port under
`profiles/<name>/bindings` is refused there (`profile '<name>' binds native port '<port>' -- the plugin binds it`).

## Example

Point the hello feature's greeting binding at `@http/http.port.json`. The domain port it used to meet is then unmet,
so a B002 per profile comes with it:

```
B003  @features/hello/data/greeting.binding.json#port
    '@http/http.port.json' is a native port; the plugin binds it
    → bind a domain port instead, or name the native operation from a graph
```

## Fix

A binding implements a domain port: set its `port` to the domain port it was meant to meet, and reach the native
operation from inside it, as a delegation (`run`) or a node of a data graph. In a profile, remove the native port's
entry (`remove it from the profile; a plugin grants its own ports`).
