# X201

- **Family:** X -- plugin rules, @storage (@wilanis/plugin-storage)
- **Status:** live, since 0.1.0
- **Made in:** `packages/plugin-storage/src/rules.ts`
- **Proved by:** `packages/plugin-storage/test/rules.test.ts` (`X201 an edge shape: the world's shape is not what a tree keeps`)

## Refuses when

A store's collection keeps a shape that is not a core shape: its `of` names a shape whose `layer` is `edge`. An edge
shape is how the world outside the tree spells a value, a request or a row of a foreign API, and what a tree keeps is
its own record of the domain, which is a core shape. A shape a plugin grants is not refused. The refusal sits at
`collections/<name>/of` of the store.

## Example

Point the `latest` collection of the customers store at the edge shape of a registration request:

```
X201  @features/customers/data/customers.store.json#collections/latest/of
    '@customers/edge/RegisterRequest.shape.json' is an edge shape, and the world's shape is not what a tree keeps
    → wilanis ls shape
```

The graph that writes the collection then fails to type against it as well (G004 in `store-and-latest.graph.json`);
it goes with the same edit.

## Fix

Name a core shape under `of`: the one the domain already declares for the record, which `wilanis ls shape` lists. If
none fits, write one under the feature's `domain/`, and translate from the edge shape where the value comes in.
