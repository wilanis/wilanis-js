# X002

- **Family:** X -- plugin rules, @http (@wilanis/plugin-http)
- **Status:** live, since 0.1.0
- **Made in:** `packages/plugin-http/src/rules.ts`
- **Proved by:** `packages/runtime/test/sabotage-project.test.ts` (`X002 a content type with no codec`)

## Refuses when

A content type is named where the `@http` plugin will read or write a body of it, and the plugin's `settings.codecs`
in `project.json` has no entry for it. The places judged are an http trigger's `settings/consumes` and
`settings/produces`, and the `consumes` and `produces` inputs of every graph node (`nodes/<id>/in/consumes`) and
binding operation (`operations/<name>/in/consumes`) that runs an operation of `@http/http.port.json`. The table is
matched without regard to case. A type with no codec would fail every request that carries it, at run time.

## Example

Make the register route consume XML, which the example's table does not map:

```
X002  @features/customers/edge/register-customer.trigger.json#settings/consumes
    content type 'application/xml' has no codec in @http settings.codecs
    → add "application/xml": "@http/codecs/<codec>.codec.json" to project.json
```

## Fix

Add the content type to `plugins → @http → settings.codecs` in `project.json`, naming a codec that `wilanis ls codec`
lists. If the content type is a typo, correct it where it is written instead.
