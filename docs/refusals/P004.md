# P004

- **Family:** P -- static fields and resolvers
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/resolvers.ts`
- **Proved by:** `packages/runtime/test/sabotage-reads.test.ts` (`P004 a read of a resolver the named document does not declare`, `P004 points at the entry that named the resolver, not at the document`)

## Refuses when

An entry under a data graph's, a binding's or a store's `reads` names no resolver. Either the resolvers document it
names declares no resolver of that name (`'<path>' declares no resolver '<name>'`, the hint listing the ones it
does), or the entry is not of the form `@path#resolver` at all (`'<ref>' is not a resolver reference`). The refusal
sits at `reads/<local name>` of the document that wrote the entry, not at the resolvers document. A resolvers
document that does not exist is R001, and one another feature does not export is L005.

## Example

A graph naming `#agents` where the document declares `agent`:

```
P004  @features/customers/data/create-row.graph.json#reads/agent
    '@customers/edge/request.resolvers.json' declares no resolver 'agents'
    → wilanis describe @customers/edge/request.resolvers.json lists its resolvers: agent, tenant
```

The body still reads `{{agent}}`, which the refused entry no longer binds, so a G003 follows at the node that reads
it and goes with this fix.

## Fix

Spell the resolver as the document declares it; the hint lists the names. If the read is new, declare it in the
resolvers document first. The not-a-reference form is usually met first as D001 on the same entry, since the schema
holds the same pattern: `"@<feature>/edge/<file>.resolvers.json#<name>"`.
