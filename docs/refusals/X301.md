# X301

- **Family:** X -- plugin rules, @otel (@wilanis/plugin-otel)
- **Status:** live, since 0.1.0
- **Made in:** `packages/plugin-otel/src/rules.ts`
- **Proved by:** `packages/plugin-otel/test/rules.test.ts` (`a bare word, which is no address at all`, `a third word,
  which would have exported at the default in silence`, `30 days, which Node would fire after 1 ms, so every stop would
  drop the unsent spans at once`)

## Refuses when

The `@otel` plugin's settings in `project.json` name an `endpoint` nothing could be sent to, or a `level` that is not
one. An endpoint must be an `http:` or `https:` URL, since the exporter posts OTLP over http, or a read of one secret
(`{{secrets.<key>}}`), whose value is taken on trust because it is not there to judge at check time. A `level` is
`summary` or `full`; any other word would silently export at the default. The rule sees the settings as written,
before any secret is substituted, which is why it can tell a literal URL from a secret read. That `endpoint` is a
string at all is C002's. A `flushDeadlineMs` is at most 2147483647 (2^31 - 1 ms, about 24.8 days): stopping waits on
the last flush with a Node timer, and Node fires a timer set longer than that after 1 ms, so every stop would drop the
spans still unsent at once. The refusal sits at `plugins/@otel/settings/<name>`: `endpoint`, `level` or
`flushDeadlineMs`.

## Example

Write the collector's address without a scheme:

```
X301  @project.json#plugins/@otel/settings/endpoint
    endpoint is "localhost:4318/v1/traces", which is neither a {{secrets.<key>}} read nor an http(s) URL, so nothing could be sent to it
    → write the collector URL (http://localhost:4318/v1/traces) or read it from a secret ({{secrets.OTLP_ENDPOINT}})
```

A `level` of `verbose` reads `level is "verbose"; a span carries either summary or full`, with the hint `level is
one of summary or full`. A `flushDeadlineMs` of 30 days reads `flushDeadlineMs is 2592000000; it is the most stopping
waits for the last spans, in milliseconds, and a Node timer waits at most 2147483647 ms (about 24.8 days): a longer one
fires after 1 ms, so every stop would drop the unsent spans at once`, with the hint `set it to 2147483647 or less, or
drop it for the default of 2000`.

## Fix

Write the collector's full URL with its scheme, or read it from a secret so each deployment names its own. For the
level, write `summary` or `full`, or leave it out for the default. For the flush deadline, write 2147483647 or less,
or leave it out for the default of 2000.

## History

- 0.1.0: introduced.
- 0.1.0: a `flushDeadlineMs` above 2147483647 is refused, since Node fires a longer timer after 1 ms (#937).
