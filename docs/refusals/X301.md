# X301

- **Family:** X -- plugin rules, @otel (@wilanis/plugin-otel)
- **Status:** live, since 0.1.0
- **Made in:** `packages/plugin-otel/src/rules.ts`
- **Proved by:** `packages/plugin-otel/test/rules.test.ts` (`a bare word, which is no address at all`, `a third word, which would have exported at the default in silence`)

## Refuses when

The `@otel` plugin's settings in `project.json` name an `endpoint` nothing could be sent to, or a `level` that is not
one. An endpoint must be an `http:` or `https:` URL, since the exporter posts OTLP over http, or a read of one secret
(`{{secrets.<key>}}`), whose value is taken on trust because it is not there to judge at check time. A `level` is
`summary` or `full`; any other word would silently export at the default. The rule sees the settings as written,
before any secret is substituted, which is why it can tell a literal URL from a secret read. That `endpoint` is a
string at all is C002's. The refusal sits at `plugins/@otel/settings/endpoint` or `plugins/@otel/settings/level`.

## Example

Write the collector's address without a scheme:

```
X301  @project.json#plugins/@otel/settings/endpoint
    endpoint is "localhost:4318/v1/traces", which is neither a {{secrets.<key>}} read nor an http(s) URL, so nothing could be sent to it
    → write the collector URL (http://localhost:4318/v1/traces) or read it from a secret ({{secrets.OTLP_ENDPOINT}})
```

A `level` of `verbose` reads `level is "verbose"; a span carries either summary or full`, with the hint `level is
one of summary or full`.

## Fix

Write the collector's full URL with its scheme, or read it from a secret so each deployment names its own. For the
level, write `summary` or `full`, or leave it out for the default.
