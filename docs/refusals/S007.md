# S007

- **Family:** S -- scenarios
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/scenarios.ts`
- **Proved by:** `packages/runtime/test/sabotage-shared-answers.test.ts` (`refuses a node digest the answers document
  does not hold, at the node, naming the file`, `refuses a stub digest held under nodes but not under stubs, at the
  stub`, `refuses a recorded scenario moved under a second recorded directory whose answers lack its digests`,
  `refuses every pointer of a recorded scenario with no answers.json above it`, `refuses every pointer into an answers
  document another command wrote`, `refuses a path both under stubs and under sharedStubs, at sharedStubs`)

## Refuses when

A recorded scenario (one with a `generated` mark) points at a value its answers document does not hold, or writes a
stub both inline and shared (RFC 0036). The answers document is the `answers.json` of the nearest directory above the
scenario, strictly below `scenarios/`, when it carries the scenario's `generated` mark (`answersFor` in
`packages/core/src/answers.ts`). A pointer does not resolve when:

- no `answers.json` is above the scenario;
- the nearest `answers.json` above it carries another `generated` mark than the scenario: a file with another mark
  is not this scenario's answers file, so `answersFor` finds none;
- the document holds no value under the digest in the map the pointer reads: `nodes` for a node of `expect.nodes`,
  `stubs` for an entry of `sharedStubs`. A digest held only in the other map does not resolve.

A pointer that does not resolve is refused at `expect/nodes/<node>` or at `sharedStubs/<path>`, one refusal per
pointer. A path that is a key of both `stubs` and `sharedStubs` is refused at `sharedStubs/<path>`: a stub is written
inline or shared, never both. What is refused is what `nodesOf` and `stubsOf` cannot resolve in the file
`answersFor` finds. Every reader of a pointer goes through these functions, so `wilanis regress`, `describe` and the
viewer read the same file the checker judged.

A scenario written by hand that points is S006's, and gets no S007 beside it. A `cancelAt` naming a path of
`sharedStubs` whose digest does not resolve is this rule's alone, not S003's.

## Example

```
S007  @scenarios/rehearsed/customers.get-customer/customers.get-row.outcome.noCustomer.scenario.json#expect/nodes/op.outcome
    node 'op.outcome' points at 57a449dbd5d11643, which @scenarios/rehearsed/answers.json does not hold under nodes
    → wilanis rehearse --record (or wilanis fuzz --edges) writes the scenarios and their answers file together: run it and review the diff
```

Where no answers document is above the scenario, the message ends `and no answers.json is above this scenario`. Where
another command wrote it, it ends `and @scenarios/rehearsed/answers.json above it is marked 'edges' where this
scenario is 'rehearse'`.

## Fix

Record the directory again with the command that owns it: `wilanis rehearse --record` for a scenario marked
`rehearse`, `wilanis fuzz --edges` for one marked `edges`. It writes the scenarios and their answers file together,
so every pointer resolves. Review the diff. A recorded scenario moved by hand into another directory is moved back,
or deleted and recorded again. Never edit `answers.json` by hand: the next record rewrites it.
