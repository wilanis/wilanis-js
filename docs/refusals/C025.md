# C025

- **Family:** C -- connections, settings and stores
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/names.ts`
- **Proved by:** `packages/runtime/test/sabotage-names.test.ts` (`C025 a native static field called connection that
  does not say names`, `C025 a native static field called store that does not say names, on a non-transactional
  operation`, `C025 a mark on a contract field that is not static`, `C025 a mark on a field that is neither a string nor
  a list of strings`, `C025 a connection kind's setting marked names that is not a string`, `C025 a mark on a shape's
  field`, `C025 a mark on a domain operation's field: a binding meets it, and reaches what the binding names`)

## Refuses when

A field says `"names": "connection"` or `"names": "store"` where the mark cannot be read, or a field the compiler
used to read by its name does not say it (RFC 0037). The compiler finds every connection a call reaches by the
fields its contract marks `names`: a connection document, or a store that names one. A profile's reach, its
`permits` (C021, C022) and the secrets `wilanis start` asks for all read those marks. So:

- a marked field is a string or a list of strings, at any depth of a contract or a connection kind's settings;
- a marked field of a native contract is `static`, since what a call names is read before anything runs;
- a shape's field and a domain operation's field mark nothing: a shape names no document, and a domain operation is
  met by a binding, which reaches what its own calls name;
- a native contract's static field called `connection` or `store` says `names`. The compiler no longer reads a field
  by its name, so without the mark it would pass the field over in silence.

The refusal points at the mark, `.../<field>/names`, or for the last case at the field itself. In practice the
document is a plugin's port.

## Example

A plugin whose port takes its connection in a static field called `connection`, written before RFC 0037:

```
C025  @http/http.port.json#operations/request/accepts/connection
    static field 'connection' does not say "names": the compiler would read no connection from it
    → the compiler reads a field by its mark, no longer by its name: add "names": "connection"
```

A mark on a field that is not static:

```
C025  @schedule/scheduler.port.json#operations/run/accepts/lease/names
    field 'lease' says "names": "connection", but is not static: what a call names is read before anything runs, so it is a literal
    → mark it "names": "connection" or "names": "store", static, of type string or string[]
```

## Fix

On a native contract, give the field `"names": "connection"` or `"names": "store"`, `"static": true`, and the type
`string` or `string[]`, as the hint says. On a shape or a domain operation, drop `names`: the native operation a
binding reaches is the one that names a connection.
