# C023

- **Family:** C -- connections, settings and stores
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/permits.ts`
- **Proved by:** `packages/runtime/test/sabotage-permits.test.ts` (`C023 an entry that is no permit: a replaced
  connection, a domain port or its operation, something pure`, `live's list on production: the reach is per
  profile, and a stand-in is what is reached`)

## Refuses when

An entry of a profile's `permits` names something that is never a permit (RFC 0016):

- a domain port or one of its operations, including a port a plugin requires: a binding meets it, and what that
  binding reaches is what a permit names;
- a `pure` operation, which reaches nothing outside the run;
- a native port with no effectful operation;
- a connection on the left of this profile's `connections` map: the tree reaches its stand-in, never it.

Such an entry is refused rather than ignored, so that a list never teaches a reader that a pure operation is an
effect or that a replaced connection is still reached. The refusal points at the entry.

## Example

Add `@connections/employees.connection.json` to the `production` profile's `permits`, where `connections` stands
`employees-production.connection.json` in for it:

```
C023  @project.json#profiles/production/permits/14
    profile 'production' permits '@connections/employees.connection.json', which this profile replaces with
    '@connections/employees-production.connection.json': the tree reaches the stand-in, not it
    → permits lists effectful native operations and connections; a domain port is met by a binding, a pure
      operation needs no permit, a replaced connection is named by its stand-in
```

## Fix

Remove the entry. For a replaced connection, name the stand-in instead; for a domain port, name the effectful native
operations its binding reaches under the profile; a pure operation needs nothing.
