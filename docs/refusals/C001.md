# C001

- **Family:** C -- connections, settings and stores
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/judge.ts`
- **Proved by:** `packages/runtime/test/sabotage-unproved.test.ts` (`C001 settings that read anything but a secret`)

## Refuses when

A settings block reads something other than a declared secret. Settings are fixed before anything is received, so
the one template they may hold is `{{secrets.<key>}}`, one key, declared under `project.json → secrets`. The rule is
`Judge.settingsRead`, and it judges every settings block the checker types: a connection's `settings`, a plugin's
`plugins/<n>/settings` in `project.json`, and a trigger's `settings`. The message names the field and says which of
three things is wrong: a read of another root (`{{request.host}}`), a secret read by a path of more than one key, or
a secret the project does not declare.

## Example

Point the customers API connection's `baseUrl` at the request:

```
C001  @connections/customers-api.connection.json#settings
    baseUrl: {{request.host}}: only {{secrets.<key>}} may appear in settings
    → declare the key under project.json → secrets
```

## Fix

Put the value in a secret: declare the key under `project.json → secrets` and write `{{secrets.<key>}}` in the
setting, or write the value as a literal. A value that depends on the request does not belong in settings at all;
pass it as an input where the operation is called.
