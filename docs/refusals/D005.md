# D005

- **Family:** D -- documents
- **Status:** live, since 0.1.0
- **Made in:** `packages/core/src/load.ts`
- **Proved by:** `packages/runtime/test/sabotage-unproved.test.ts` (`D005 no project.json at the root`)

## Refuses when

The directory being loaded has no `project.json` at its root. Without it the loader has no plugins, aliases,
profiles or includes to read, so what depends on them is refused beside it: an include's plugins come back as D010.
The CLI answers a missing `project.json` with a line on stderr before it loads anything; D005 is what the loader
answers when it is handed such a directory, as a tool that calls `loadTree` does. There is no `at`.

## Example

Delete `project.json` from a copy of the example:

```
D005  project.json
    no project.json at the root
    → wilanis new project <name>
D010  project.json#includes/0
    '@wilanis/access' uses plugin '@std', which this project does not name
    → add { "use": "@std" } to project.json → plugins, with the settings its README says
```

## Fix

Run the command in the hint, or check that the path handed over is the tree's root and not a directory inside it.
