# G009

- **Family:** G -- graphs
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/graph-nodes.ts`
- **Proved by:** `packages/runtime/test/sabotage-unproved.test.ts` (`G009 a switch that routes to a node the graph does not declare`)

## Refuses when

A switch's `to` or `else` names a node that is not in the graph (`routes to unknown node '<id>'`), names the switch
itself (`switch routes to itself`), or names a node another switch already routes (`node '<id>' is routed by both
'<a>' and '<b>'`). A routed node runs only when its switch chooses it, so it has exactly one router. The refusal sits
at the switch, `nodes/<id>`.

## Example

Route the first rule of `list-rows`'s `outcome` to a node that does not exist:

```
G009  @features/customers/data/list-rows.graph.json#nodes/outcome
    routes to unknown node 'nowhere'
    → name a node declared under nodes, or add it
```

A G004 and a G010 follow: the node the rule used to route is no longer behind the switch, so what it reads may be
missing and it is an `out.from` candidate that is never routed.

## Fix

Name the node the rule meant, or add it under `nodes`. A switch routes to other nodes only; a graph has no loop. Where
two switches route one node, one decision is split across them: route it from one switch, and make the other decide
something else.
