# P002

- **Family:** P -- static fields and resolvers
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/resolvers.ts`
- **Proved by:** `packages/runtime/test/sabotage-reads.test.ts` (`P002 a resolver reading a path no trigger kind hands`)

## Refuses when

A resolver in a `resolvers` document reads a `request.*` path that no trigger kind of the tree hands and the guard
does not add. A resolver is a read of the request and nothing else, so a path nothing hands could never be answered.
The refusal sits at `resolvers/<name>/read`. Whether the particular kinds that reach a read hand it is a separate
question, judged at the trigger (T004).

## Example

```
P002  @features/customers/edge/request.resolvers.json#resolvers/agent/read
    resolver 'agent': no trigger kind hands request.nowhere.session
    → wilanis describe <trigger kind> shows what each kind hands as request.*
```

A refused resolver is not declared, so every document that reads it is refused as well: P004 at its `reads` entry
and G003 where the name is read. Both follow from this one.

## Fix

Correct the path to one a kind hands: `wilanis describe` on the trigger kind lists its `request.*` context, and the
guard's plugin lists what it adds (`request.principal`, `request.session`, `request.challenge`). A value that is not
in the request is not a resolver's to read; pass it through the trigger's `fire.in` instead.
