# D000

- **Family:** D -- documents
- **Status:** live, since 0.1.0
- **Made in:** `packages/core/src/documents.ts`, `packages/core/src/load.ts`
- **Proved by:** `packages/runtime/test/sabotage-unproved.test.ts` (`D000 a file that is not JSON`)

## Refuses when

A `.json` file the loader reads does not parse as JSON: `project.json`, any document under the tree, or a document a
plugin ships under its `docs/`. The message carries the parser's own words, which usually name the position. A file
that does not parse is never registered, so what names it is refused as well; when the file is `project.json`, the
project's plugins and aliases are never declared, and an include's plugins come back as D010. There is no `at`: the
refusal is about the file as a whole.

## Example

Cut `project.json` short:

```
D000  project.json
    not JSON: Unexpected end of JSON input
    → fix the JSON at the position the parser names
D010  project.json#includes/0
    '@wilanis/access' uses plugin '@std', which this project does not name
    → add { "use": "@std" } to project.json → plugins, with the settings its README says
```

## Fix

Repair the JSON: a missing brace or quote, a trailing comma, a comment. Check again before reading the refusals
below it, since what follows a D000 is usually its shadow: the D010s above go once the project parses.
