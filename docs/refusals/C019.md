# C019

- **Family:** C -- connections, settings and stores
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/project.ts`
- **Proved by:** `packages/runtime/test/sabotage-profiles.test.ts` (`C019 a secret nothing reads`)

## Refuses when

A key under `project.json → secrets` is read by nothing. A document reads a secret as `{{secrets.<key>}}` in three
places: a plugin's `settings`, a connection's `settings`, and a startup step's `in`. A key none of them reads still
names an environment variable that every place the tree runs must set, for nothing. The refusal points at
`secrets/<key>` and names the variable the key maps to.

## Example

Declare a secret `unused`, mapped to `UNUSED_SECRET`, that no document reads:

```
C019  @project.json#secrets/unused
    secret 'unused' (UNUSED_SECRET) is read by nothing: no plugin's settings, no connection's settings, no startup step's in
    → remove it from project.json → secrets, or read it as {{secrets.unused}}
```

## Fix

Remove the key from `secrets` if nothing needs it. If a setting should read it, write `{{secrets.<key>}}` where the
value belongs, in one of the three places above.
