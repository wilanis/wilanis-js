# X253

- **Family:** X -- plugin rules, @schedule (@wilanis/plugin-schedule)
- **Status:** live, since 0.1.0
- **Made in:** `packages/plugin-schedule/src/rules.ts`
- **Proved by:** `packages/runtime/test/sabotage-schedule.test.ts` (`X253 catchUp while the example's run step names no lease`)

## Refuses when

A scheduled trigger sets `catchUp` to `true` while no startup step runs `@schedule/scheduler.port.json#run` with a
`lease`. Catching up fires the ticks missed while nothing ran, and knowing which were missed needs the last tick
remembered where every process sees it, which is what the lease keeps. The refusal sits at `settings/catchUp`.

## Example

Set `catchUp` on the planted nightly trigger, with the example's run step as it is:

```
X253  @features/hello/edge/nightly-greeting.trigger.json#settings/catchUp
    catchUp is true while no startup step names @schedule/scheduler.port.json#run with a lease: no process can know what the last tick was
    → give the run step a lease ({ "in": { "lease": "@connections/<store>.connection.json" } }), or drop catchUp
```

## Fix

Give the run step in `project.json → startup` a `lease` on a connection whose kind keeps leases (X254 judges that
connection), or drop `catchUp` and let a missed tick stay missed.
