# L011

- **Family:** L -- layers, effects and visibility
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/atomic.ts`
- **Proved by:** `packages/runtime/test/sabotage-atomic.test.ts` (`is refused where nothing it reaches could roll
  back -- L011`)

## Refuses when

A graph marked `"atomic": true` reaches no transactional effect under any profile, so there is nothing for the
transaction to commit or roll back. A graph that only reads a store is not refused: a store read takes part, and an
atomic read-only graph is a consistent snapshot. The judgement is over every walk, including a graph no profile
reaches, since what its own nodes run is enough to say. `at` is `atomic`.

## Example

Mark the customers `parse-drafts` data graph atomic; it only parses a file:

```
L011  @features/customers/data/parse-drafts.graph.json#atomic
    atomic graph reaches no effect that can take part in a transaction
    → nothing here can roll back; delete "atomic"
```

The same edit earns an L009 for the parse itself, which cannot take part either.

## Fix

Delete `atomic`. If the graph was meant to be the transaction around writes, mark the graph that reaches them
instead.
