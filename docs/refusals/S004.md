## Refuses when

A scenario's `branch` names a decision the tree does not have. `branch` says what the scenario proves: the graph that
declares a switch (`graph`), the switch's node id (`node`), the rule's expression (`when`) and the node the rule routes
to (`to`). The refusal sits where the branch stops matching the tree:

- at `branch/graph`, when `graph` names no graph document;
- at `branch/node`, when `node` is no node of that graph, or a node that is not a switch; the message lists the
  graph's switches;
- at `branch/to`, when `to` is neither a rule's `to`, the `else`, nor where the switch's `catch` routes a node that
  broke; the message lists every node the switch routes to.

`when` is not judged. A rule's text is the solver's to compare, and a hand-written scenario may carry `"when": "else"`
or a paraphrase. A catch target counts as a branch because the rehearsal walks each caught node as a case of its own.

## Example

```
S004  @scenarios/rehearsed/get-customer/customers.get-row.outcome.noCustomer.scenario.json#branch/to
    the branch names node 'gone' of switch 'outcome' in @features/customers/data/get-row.graph.json, which no rule of the switch routes to: it routes to noCustomer, customer, upstreamFailed, unreachable
    → wilanis rehearse --record rewrites scenarios/rehearsed/ from the tree as it stands; a hand-written scenario names a node the switch has
```

## Fix

A recorded scenario (`generated: "rehearse"`) is regenerated, never edited: `wilanis rehearse --record` writes
`scenarios/rehearsed/` again from the tree, and the renamed or removed branch becomes a file of its new name, or none.
A hand-written scenario is edited to name the graph, switch and target the tree has now, which the message lists; if
the decision it proved is gone on purpose, delete it.
