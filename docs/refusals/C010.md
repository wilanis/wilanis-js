# C010

- **Family:** C -- connections, settings and stores
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/stores.ts`
- **Proved by:** `packages/runtime/test/sabotage-storage.test.ts` (`C010 a renamed keyed by a field the shape does not have: there is nothing to rename to`); `packages/runtime/test/sabotage-storage.test.ts` (`C010 a renamed whose value is a field of the shape still, so nothing was renamed`)

## Refuses when

A collection's `renamed` does not describe a rename. It is keyed by the field's name now and holds the name it had
before, so the key is a field of the shape, the value is a field the shape no longer has, and no two keys claim the
same former name, since one column cannot become two. Each entry answers at most one refusal, at
`collections/<name>/renamed/<field>`. The key may be the collection's own key.

## Example

Key `renamed` by a field the shape does not have:

```
C010  @features/customers/data/customers.store.json#collections/customers/renamed/nope
    'nope' is not a field of @customers/domain/Customer.shape.json (fields: id, name, email, tier, registrar, active, note)
    → renamed is keyed by the field's name now and holds its name before: wilanis describe @customers/domain/Customer.shape.json
```

Name a field the shape still has as the old name, and it says `'tier' is a field of
@customers/domain/Customer.shape.json still, so nothing was renamed to 'email'`.

## Fix

Write the entry the other way round if it was reversed: the current field as the key, the old column name as the
value. Drop an entry whose old name is still a field, since nothing was renamed, and give each former name to one
field only.
