# G015

- **Family:** G -- graphs
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/graph-reads.ts`
- **Proved by:** `packages/runtime/test/sabotage-routing.test.ts` (`G015 refuses each write of the toggle, and nothing else`)

## Refuses when

A node that runs an effect (an operation not marked `pure`) is the `to` of no switch rule, and every node that reads
its answer runs behind some branch of a switch, so on the other branches the effect ran for nothing. A node runs as
soon as what it reads is ready, whatever a switch chose: a switch decides who answers, not who runs. Most often this
is a write the author meant one branch to make, written beside the switch instead of under it. The message names the
first readers behind a branch, where the answer enters one. An effect `out.from` names is the graph's answer and is
not refused; one nothing reads at all is G008's, not this rule's. The refusal sits at the effect's `nodes/<id>`.

A node waits for what it names under `after` as it waits for what it reads (RFC 0041). So an effect that waits for a
node a switch routes is routed, and is not refused. A node that only waits for the effect counts as a reader of it.
Where the first readers sit behind exactly one target of one switch, the hint also offers to make the effect wait for
that target, `"after": ["<target>"]`. Where they sit behind several targets, or behind more than one switch, it does
not: `after` waits for every node it names, never for one of them.

## Example

Rewrite `keep-customer` as a toggle whose two `#patch` writes sit beside the switch that decides between them, each read
only by the check under its own branch:

```
G015  @features/customers/data/keep-customer.graph.json#nodes/activate
    effect 'activate' runs on every branch, but its answer is read only under 'checkActivate'
    → route the effect under the branch that reads it: make 'activate' the 'to' of the switch rule that leads to 'checkActivate', or read its answer from every branch
```

## Fix

Make the effect the `to` of the switch rule that leads to its reader, in place of the reader: `"to": "activate"`
where the rule said `"to": "checkActivate"`. The write then runs only on that branch, and the reader, which reads it,
runs after it. If the effect is meant to run on every call, read its answer from every branch instead.

When the rule must keep routing to the node it routes to, because that node reads what the rule proved, let the
effect wait for that node instead: `"after": ["customer"]`. The effect then runs only on that branch, and the node
keeps the proof.
