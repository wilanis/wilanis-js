# B002

- **Family:** B -- bindings, profiles and startup
- **Status:** live, since 0.1.0
- **Made in:** `packages/compiler/src/check/profiles.ts`
- **Proved by:** `packages/runtime/test/sabotage-project.test.ts` (`B002 a domain port with no binding once the profile is gone`), `packages/runtime/test/required-port.test.ts` (`B002 under every profile while nothing binds it, naming the plugin that requires it`)

## Refuses when

Every domain port is met by exactly one binding under every profile the project declares, or in the tree as a whole
where it declares none. A profile chooses among several bindings in `project.json → profiles/<name>/bindings`;
without a choice, a port needs exactly one binding. The message says which of three things went wrong: no binding
implements the port, the port has several and nothing chooses, or the profile names a binding that does not exist.
Under a profile the refusal sits on the project at `profiles/<name>/bindings`; without profiles it sits on the port.
A port a plugin requires (RFC 0005), such as `@auth/state.port.json`, is judged the same way, and the message names
the plugin, since the tree never wrote that port.

A port is judged under every profile, whether or not the profile serves the triggers that reach it (A006 says
which profile serves which trigger): the refusal sits at that profile's own bindings, so it is never the same edit
twice.

## Example

Delete the binding of the guard's memory from the example, and `@auth/state.port.json` is unmet under `live` and
`local`, the two profiles that choose it (R001 comes with it, since the profiles still name the binding):

```
B002  @project.json#profiles/live/bindings
    profile 'live': profile 'live' names unknown binding '@features/state/data/auth-files.binding.json' for '@auth/state.port.json' (required by @auth)
    → wilanis new binding <feature>/<name> --port @auth/state.port.json
```

With the profiles removed and nothing binding the customer port:

```
B002  @features/customers/domain/customer.port.json
    no binding implements port '@features/customers/domain/customer.port.json'
    → wilanis new binding <feature>/<name> --port <path>
```

## Fix

Write the binding (`wilanis new binding <feature>/<name> --port <port>`), in the `data/` of the feature that owns the
port, or of a feature of its own for a port a plugin requires. Where the port has several bindings, choose one under
each profile in `project.json → profiles`. Where the profile names a binding that does not exist, correct the path.
