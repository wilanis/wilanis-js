Example refusal · L009

A Redis lease inside a database transaction

Registering a customer writes two rows in one "atomic": true graph. Suppose someone adds a Redis lease so two registrations of the same tier never race:

{
  "id": "tierLease",
  "run": "@redis/lease.port.json#acquire",
  "in": { "key": "tier:{{in.tier}}", "ttlMs": 5000 }
}

The transaction can roll back. The lease cannot. If the second write fails, the rows vanish and Redis still says the tier is held for five seconds. Check, 0.64 s:

G008  @features/customers/data/store-and-latest.graph.json#nodes/tierLease
    node 'tierLease' is read by nothing
    → nothing routes to 'tierLease', so it runs on every branch: make it the 'to' of a switch rule, or read its answer from every branch
L009  @features/customers/data/store-and-latest.graph.json#nodes/tierLease
    atomic graph '@features/customers/data/store-and-latest.graph.json' reaches '@redis/lease.port.json#acquire', which cannot take part in a transaction (profile 'local')
    → read or send that outside the transaction: in the caller for a domain graph, in a graph of its own for a data graph

Three findings from one node. The lease is outside the transaction it sits in. The CSV import's batch graph, two documents up, reaches it too and makes the same promise. And nobody reads whether the lease was actually taken.

wilanis ships no Redis plugin yet (RFC 0030 plans a Redis cache kind, not a lease). The run used a 20-line stub plugin declaring one port with no transactional marker, which is all the rule looks at. Marking the example's CSV import atomic trips the same rule with @http/http.port.json#request and @blob/csv.port.json#parse.

What unit tests usually hold

  • the handler calls the right repository
  • types line up across layers
  • each if branch is reached
  • the 401 fires without a token
  • the output did not change

Who holds it in a wilanis tree

  • no handler exists; check proves the wiring
  • check, under every profile
  • rehearse, which solves for each rule
  • check (A, T) and rehearse
  • regress, naming the node that moved

A tree has no code of its own to unit-test. The code lives in plugins, tested once in their own packages. What rehearsal cannot tell you is how the real Postgres or upstream API answers, since it stubs them; that stays an integration test.
